## Genkit Agents API：全栈 Agentic 应用框架发布【⭐⭐⭐】
**来源：** Google AI
**链接：** https://developers.googleblog.com/build-agentic-full-stack-apps-with-genkit/
**关键词：** Genkit, Agents API, 全栈框架, 会话管理, 中断式工具, 多Agent协作

### 摘要
Google 在 Genkit（开源全栈 AI 框架）中发布了 **Agents API**（Preview 阶段），支持 TypeScript 和 Go。核心理念是把 Agent 的"水管工工作"——消息历史、工具循环、流式输出、持久化、前后端协议——统一封装到一个接口里。

**关键特性：**
- **统一的 chat() 接口**：无论是本地调用还是通过 HTTP 端点，都使用相同的 API
- **双模式会话管理**：server-managed（服务端持久化，通过 Firestore 等存储 snapshots）和 client-managed（客户端自行管理状态），支持从任意 snapshot 分支恢复对话
- **中断式工具（Interruptible Tools）**：工具可以暂停 Agent 等待人工审批，适用于支付、部署等高风险操作，运行时会对恢复载荷做校验防伪造
- **Detach 机制**：长任务可以脱离客户端继续运行，客户端可稍后通过 snapshot ID 重连获取结果
- **Agent 协作**：通过 Agents 中间件实现 orchestrator + specialists 模式，子 Agent 的 artifacts 可合并到父会话
- **前端集成**：提供 `remoteAgent()` JavaScript 客户端，支持流式输出和 Vercel AI SDK 适配器
- **Developer UI**：内置 Agent Runner，可直接在 UI 中测试对话、工具中断和 snapshot

Genkit 被定位为"应用原语"，适合嵌入全栈用户面应用；如果需要复杂多 Agent 拓扑和托管运行时，Google 建议使用 ADK。

## VS Code 集成 Google Cloud Workbench：本地 IDE 直连云上 ML 算力【⭐⭐】

**链接：** https://developers.googleblog.com/ml-development-in-vs-code-with-google-cloud-power-workbench-extension-now-available/
**关键词：** VS Code, Google Cloud, Workbench, Jupyter, ML开发

### 摘要
Google 发布了 **Google Cloud Workbench Notebooks** VS Code 扩展（已开源），让数据科学家在本地 VS Code 中直接连接云端 Workbench 实例运行 Jupyter Notebook。

**核心价值**：消除本地开发和云端高性能计算之间的上下文切换。开发者用本地 IDE 的配置和扩展，通过选择 kernel 切换到 Workbench 实例即可获得云端算力。扩展已上架 VS Code Marketplace，代码开源在 GitHub。

## ADK 2.0：为什么 Agent 需要确定性工作流【⭐⭐⭐】
**来源：** Google AI
**链接：** https://developers.googleblog.com/why-we-built-adk-20/
**关键词：** ADK 2.0, 工作流引擎, 确定性执行, 混合架构, Agent 协作

### 摘要
Google 详细阐述了 ADK 2.0 的设计哲学：**不是 Agent vs 代码的二选一，而是有向图工作流 + LLM Agent 的混合架构**。

**核心论点：**
- LLM 擅长创造性推理，但不擅长严格按步骤执行——让模型做编排既慢又贵还不稳定
- 业务逻辑（如退款流程：验证购买→查政策→退款→发邮件→关工单）应该是确定性有向图，每一步用代码路由，只在需要处理非结构化输入（如分析投诉内容、起草邮件）时才调用 LLM
- 实测对比：纯 Agent 方式 5152 tokens / 7.2s，ADK 2.0 Workflow 方式 2265 tokens / 5.7s，**token 省 ~50%，延迟降 ~20%**

**ADK 2.0 新能力：**
- **Workflow 图引擎**：节点可以是 Tool、Agent 或路由函数，支持条件分支、循环、子工作流
- **动态工作流**：允许用原生 Python 控制流表达复杂动态逻辑，不必写静态路由表
- **结构化多 Agent 协作**：不同 Agent 收不同的上下文，Policy Agent 只收政策文档，Email Agent 只收客户信息，避免 context bloat
- **安全性**：执行路径由代码控制，即使 LLM 被 prompt injection 攻破，工作流图也没有执行未授权操作的路径
- **模式控制**：支持 Task 和 Single-turn 模式，让 Agent 专注于单一职责

**选型建议**：执行顺序明确 → Workflow；处理非结构化输入 → Agent；两者结合 → ADK 2.0 Agentic Workflow。

ADK 2.0 目前已在 Python 可用，刚刚推出 Go 支持。

## 别再把AI培训丢给HR了：它是CEO主导的系统性变革工程【⭐⭐】

**关键词：** AI转型, 组织变革, CEO领导力, 培训体系

麦肯锡中国发文指出，AI 培训不应被简单外包给 HR 部门处理，而是需要 CEO 亲自挂帅的系统性变革工程。文章强调 AI 能力建设不是"上几门课"就能解决的问题，需要从战略、文化、流程、人才四个维度进行顶层设计。CEO 需要理解 AI 对业务模式的重塑潜力，并亲自推动组织层面的行为改变。仅靠 HR 主导的培训项目往往停留在表面技能提升，无法驱动真正的业务转型。
