## Getting started with loops — Claude Code 官方定义 Agentic Loop【⭐⭐⭐】
**来源：** Claude Blog
**链接：** https://claude.com/blog/getting-started-with-loops
**关键词：** Claude Code, agentic loops, /goal, /loop, /schedule, 工作流设计

### 摘要

Anthropic Claude Code 团队发布了关于 agentic loop 的正式定义和实践指南，把最近热议的 "设计 loop 而不是写 prompt" 做了系统化阐述。

核心定义：**Agentic Loop = Agent 重复执行工作循环，直到满足停止条件。**

四种 Loop 类型：

1. **手动循环（Manual Loop）** — 每个 prompt 启动一轮。你发指令，Claude 读代码→改代码→测试→返回结果，你人工检查后再发下一轮。适用于短任务、非周期性工作。改进方式：把人工验证步骤编码成 SKILL.md。

2. **目标循环（/goal）** — 定义"完成"的标准，Claude 自动迭代直到目标达成或达到最大轮数。核心技巧：用确定性指标（如测试通过数、Lighthouse 分数）而非模糊描述。例：`/goal get the homepage Lighthouse score to 90 or above, stop after 5 tries`。每轮由 evaluator model 检查条件决定是否继续。

3. **时间循环（/loop 和 /schedule）** — 按时间间隔触发。`/loop 5m check my PR...` 在本地运行；`/schedule` 把循环搬到云端。适合周期性任务（如每天早上总结 Slack 消息）或对接外部系统（如监控 PR 评审和 CI 状态）。

4. **主动循环（Proactive Loops）** — 无人在回路，由事件或调度触发，每个子任务用 /goal 定义完成标准，整体 routine 持续运行直到手动关闭。适合 Bug 报告处理、Issue Triage、依赖升级等大规模重复性工作。

代码质量建议：干净的代码库是第一位的（Claude 会遵循已有模式）；引导 Claude review 自己的 PR 如同对同事一样；路由简单任务到小模型，只在需要判断时才用强模型。

## Claude Science：AI 科学家工作台正式发布【⭐⭐⭐】
**来源：** Anthropic News
**链接：** https://www.anthropic.com/news/claude-science-ai-workbench
**关键词：** Claude Science, 生命科学, AI工作台, 科学计算, 可复现研究

### 摘要

Anthropic 发布 Claude Science，一个专为科研人员打造的 AI 工作台应用，面向生命科学领域。这是 Anthropic 自去年秋季进入生命科学领域以来最大的一次扩展。

核心能力：

- **统一研究环境**：把 PubMed、Jupyter、R、集群终端等碎片化工具体验整合到一个对话式界面。用户用自然语言提问，Agent 自动查询 UniProt、PDB、Ensembl、ClinVar、ChEMBL、GEO 等超过 60 个科学数据库并综合回答。内置 60+ 预配置技能和连接器，覆盖基因组学、单细胞、蛋白质组学、结构生物学、化学信息学等领域。
- **可复现的科学产物**：生成的图表、稿件附带完整代码、运行环境和消息历史。支持原位渲染 3D 蛋白结构、基因组浏览器轨道、化学结构等。用自然语言修改图表（如"去掉网格线""换成对数刻度"），Agent 会自己改代码。
- **计算资源管理**：在用户的笔记本、Linux 机器或 HPC 登录节点上运行，敏感数据无需离开已有的系统。大任务自动 Draft 方案、询问确认后才提交到集群。集成 Modal 实现 GPU 算力按需扩展到数百块。
- **审核 Agent**：内置 reviewer agent 检查引用、核对数字与底层代码是否一致，发现错误自动修正。

Claude Science 今日起在 Beta 版中对 Claude Pro/Max/Team/Enterprise 用户开放。在封闭测试中，研究人员已用于单细胞 RNA-seq 分析、CRISPR 筛选设计、蛋白质结构预测、化学信息学等任务。

对比：比 Jupyter Notebook 更像一个完整的研究操作系统——不是替代单个工具，而是把所有工具和 Agent 整合在一个可追溯的工作流里。

## Claude Sonnet 5：迄今最 Agentic 的 Sonnet【⭐⭐⭐】
**来源：** Anthropic News
**链接：** https://www.anthropic.com/news/claude-sonnet-5
**关键词：** Claude Sonnet 5, agentic model, coding, tool use, 性价比

### 摘要

Anthropic 发布 Claude Sonnet 5，定位为"最 Agentic 的 Sonnet 模型"——能制定计划、使用浏览器和终端工具、自主运行，性能接近 Opus 4.8 但价格更低。

关键数据与特性：

- **性能对标**：在推理、工具使用、编码、知识工作等核心维度上相比前代 Sonnet 4.6 大幅提升；在高 effort 设置下能在 BrowseComp 和 OSWorld-Verified 等 agentic 评测上匹配 Opus 4.8。
- **定价**：推广期（截至 2026/8/31）$2/M input tokens + $10/M output tokens；正式定价 $3/M input + $15/M output。对比 Opus 4.8 的 $5/$25，性价比优势明显。
- **安全**：整体不良行为率低于 Sonnet 4.6，Agent 场景更安全；网络安全能力远低于 Opus 模型，更适合广泛分发。
- **今日上线**：全平台可用，成为 Free/Pro 计划的默认模型；API 通过 claude-sonnet-5 调用。

早期使用者的反馈很一致：Sonnet 5 在复杂任务上能从头到尾做完（之前 Sonnet 会在中间停下），会自发检查输出，而且以更低成本做到这些。Rust 工程师 Neel Chotai 举例：让 Sonnet 5 查一个 bug，它主动写了复现测试、实现了修复、还 stash 了修改来确认 bug 消失——全程一次完成。

值得关注的变化：Anthropic 开始强调 effort level（effort）作为价格-性能调节旋钮，Sonnet 5 的 cost-performance 曲线比 Opus 4.8 宽得多，用户可以根据任务复杂度在不同 effort 之间选择。

## Fable 5 出口管制解除，7月1日起全球恢复访问【⭐⭐⭐】
**来源：** Anthropic News
**链接：** https://www.anthropic.com/news/redeploying-fable-5
**关键词：** Fable 5, export control, 出口管制, 安全分类器, jailbreak

### 摘要

Anthropic 宣布 Fable 5 和 Mythos 5 的出口管制已于 6月30日解除。Fable 5 将于 7月1日（今天）起全球恢复访问；Mythos 5 仅限部分美国组织。

事件回顾：

- **6月9日**：发布 Fable 5 和 Mythos 5。两者共享底层模型，但 Fable 5 带有强安全护栏，Mythos 5 仅面向 Glasswing 合作伙伴的防御性网络安全使用。
- **6月12日**：美国政府因亚马逊研究者发现了一个绕过 Fable 5 安全护栏的 jailbreak 方法，对这两个模型施加出口管制，Anthropic 暂停了所有用户的访问。
- **后续调查**：测试发现包括 Claude Opus 4.8、GPT-5.5、Kimi K2.7 在内的多个较弱模型也能完成同样的操作，所有被测模型都能生成相同的漏洞利用演示。这并不代表 Fable 5 暴露了独特的 Mythos 级网络能力。
- **6月30日**：管制解除。Anthropic 训练了改进版安全分类器，对报告中的绕过方法拦截率超过 99%。NIST 下属 CAISI 测试确认新旧安全措施都"非常强大"。

后续安排：Pro/Max/Team/部分 Enterprise 用户可在 7月7日前使用 Fable 5（占每周额度的 50%），之后需通过 usage credits；AWS/GCP/Azure 将尽快恢复。

另有两项值得关注的产业动态：
1. Anthropic 与 Amazon、Microsoft、Google 等 Glasswing 伙伴共同开发 jailbreak 严重性评估的共享行业框架，以帮助 AI 开发者在发布高能力模型时更安全地应对新发现的安全漏洞。
2. Anthropic 正在加强与美国政府的合作，包括发布前测试、信息共享和研究协作。

## Google ADK Go 2.0：图驱动工作流引擎 + 多 Agent 编排【⭐⭐】
**来源：** Google AI
**链接：** https://developers.googleblog.com/announcing-adk-go-20/
**关键词：** ADK Go 2.0, Google, multi-agent, graph workflow, human-in-the-loop

### 摘要

Google 发布 Agent Development Kit (ADK) Go 2.0，为构建可靠的多 Agent 应用提供了全新的图驱动工作流引擎（graph-based workflow engine）。

核心特性：

- **图驱动工作流引擎**：用图结构定义多 Agent 之间的调用关系和执行顺序，替代线性的链式调用，使复杂的 Agent 编排更可控和可调试。
- **内置 Human-in-the-Loop**：在执行关键步骤时自动暂停等待人工审批或输入，不需开发者自行实现。
- **动态编排**：Agent 可以根据运行时状态动态调整执行路径，而非完全预设。

Go 语言实现意味着更适用于生产环境的高并发和低延迟场景，面向的是将 AI Agent 真正部署到企业级系统的开发者群体。与 LangGraph 等 Python 生态的多 Agent 框架形成互补——Google 显然是盯上了 Go 生态里那些已经在用 gRPC、Kubernetes 等基础设施的工程团队。

Ollama 0.31 引入 Multi-Token Prediction（MTP）支持，使 Gemma 4 在 Apple Silicon 上的推理速度平均提升近 90%（基于 Aider polyglot 编码 Agent 基准测试）。

技术原理：

- **推测解码**：Gemma 4 自带一个小型 draft model（体积远小于主模型），每次预测几个 token 候选，主模型一经验证就批量接受正确的 token。因为 draft model 非常小，提案成本很低，正确率高时相当于一次计算产出多个 token。
- **代码场景优势明显**：代码充满闭合括号、重复标识符、固定模板，Draft model 的提案更容易被接受，因此编码 Agent 受益最大。
- **自适应 Draft 长度**：Ollama 在运行时自动追踪提案接受率和每次验证耗时，动态调整 draft token 数量。当接受率下降时自动退回标准逐个解码，不会产生额外性能损耗。
- **MLX 核优化**：向 MLX 贡献了专用的推测解码 kernel，将 Gemma 4 最大矩阵乘法的速度提升了 2×-2.5×。效果来自避免重复读取权重——一次读取、整个 batch 复用。

无需任何配置，升级到 Ollama 0.31 即可自动启用。已下载的 Gemma 4 需要 ollama pull 重新拉取以获得 MTP 支持版本。Ollama 表示更多模型将陆续获得此优化。
