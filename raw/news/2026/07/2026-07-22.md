## Datadog 如何为 Claude Code 打造「通用机床」Temper【⭐⭐⭐】

**来源：** Claude Blog (Anthropic)
**链接：** https://claude.com/blog/how-datadog-built-a-universal-machine-tool-for-claude-code
**关键词：** 软件工业化 / 智能体规范驱动 / 形式化验证 / 暗工厂 / Datadog / Temper

### 摘要

Anthropic 官方博客发表了一篇深度案例文章，详细讲述 Datadog 如何从 AI 辅助编码逐步走向「软件工业化」。

**背景与规模：** Datadog 所有工程师都在用 AI 编程工具写生产代码，Claude Code 驱动了至少三分之二的量。工作范围从针对性修复（bug fix、性能优化），到大重构（三天重写 protobuf 解析器、三个月迁移 metrics 控制层从 FoundationDB 到 Postgres），再到构建完整系统（替换 MongoDB 为 Postgres、BYOC 控制面、从头构建 ingestion pipeline）。

**核心问题——流程的断裂：** Datadog 工程 VP Sesh Nalla 指出，智能体让工程师的角色发生了根本变化——「你不再写代码，你在塑造工作」。工程师被往上提拔了三级变成管理者，而他们并没有为此做好准备。智能体的 session 能跑几天，每个智能体发明自己的工具、粘合代码和惯例——功能更强了，但需要人类来弥合智能体执行与人类工具之间的鸿沟。

**工业化三阶段：**
1. **Courier（2024）**：分布式队列系统，纯人工构建耗时一年。核心认知——「难的不是构建部件，而是让部件之间的交互可测试、可验证」。引入形式化建模和仿真，在错误代价高或难以逆转的地方提升严谨度。
2. **BitsEvolve（2025年9月）**：闭环进化优化框架。一个模型「委员会」生成代码变体，级联式的基准测试、单元测试加生产可观测性决定哪些代码存活。Sesh 评论：「我第一次看到软件的部分可以像有机体一样被培育——通过变异+反馈+适应来生长」。
3. **Helix**：Kafka 兼容的流式服务，Claude Code 完成大部分构建，一个人掌控方向。几天内就有了功能完整的系统，发现有机会达到 2-5 倍成本降低。但投产花了大量时间——运维硬化只能在时间中积累，且仍需多人协调。

**Temper 是什么：** 一言蔽之，Datadog 的「通用机床」——智能体不直接产代码，而是产生**规范（specification）**。Temper 内核读取规范，通过四层独立分析验证后部署运行系统：

- **符号推理**：证明每个 guard 可满足且每个 invariant 是归纳的
- **穷举状态探索**：访问所有可达状态
- **确定性仿真**：用生产代码跑带故障注入的确定性仿真（drop、延迟、重排、崩溃），相同种子得出的失败可精确复现
- **随机属性测试**：约 1000 次伪随机动作序列，将任何违规缩至最小反例

小规范四层级联在远不到一秒内完成。

**三个契约维度：**
- **行为契约**：状态、转换、前置条件、安全属性
- **数据契约**：实体类型、属性、支持的动作，以机器可解析形式发布，智能体无需文档即可发现完整 API
- **授权契约**：default-deny + 基于 scope 的审批，拒绝记录为待处理决策，人类可批准并热加载到策略引擎

**暗工厂（Dark Factory）：** Simon Willison 流行的这个概念在 Datadog 落地——Temper 在 Helix 暗工厂中扮演三个角色：智能体控制面（sessions、角色、工作队列、生命周期）、工具构建层（让智能体桥接 Git/CI/部署等 SDLC 工具）、Helix 控制 API。

**为什么不用 CRUD 应用：** Sesh 解释，普通 CRUD 应用中控制逻辑分散在路由、数据库约束、服务代码、后台任务和文档中——状态机隐含在代码库里。Temper 让状态机显式化。智能体产出精确描述而非任意代码。编译步骤在 LLM 之外，和 Rust 代码交给 Rust 编译器一样。转换表是数据，不是散落在服务方法中的意大利面控制流。

**Datadog 的最佳实践建议：**
1. 你的真正瓶颈是生成还是验证？假设是验证——智能体产生代码比团队审查快得多，生成与验证之间的鸿沟才是故障积累处
2. 智能体应该产出什么？控制逻辑的规范（而非代码）+ 任意代码的证明承载。把编译和证明放到 LLM 外部
3. 你的控制逻辑是显式的还是散落在代码库各处？把状态机从路由、服务方法、后台任务中抽出来做成数据
4. 人类是否能把每个产物装进脑袋里理解？如果不是，你又回到了原点。让每块产物小到可以推理

**趋势判断：** 这篇文章不是简单的案例宣传，而是 Anthropic 通过 Datadog 的实践在阐述一个软件工程范式转变——从「AI 写代码」到「AI 写规范 + 确定性内核验证部署」。工业革命之所以可能，是因为机床让零件可组合、可检查、可替换。Temper 就是软件世界的机床。

## Anthropic 副 CISO 详解 AI 原生 SDLC 安全实践【⭐⭐⭐】

**来源：** Claude Blog
**链接：** https://claude.com/blog/how-anthropic-secures-its-ai-native-software-development-lifecycle
**关键词：** SDLC 安全 / AI 生成代码占比 80% / Jason Clinton / Anthropic 安全工程

### 摘要

Anthropic 副 CISO Jason Clinton 撰文详细介绍了 Anthropic 安全工程团队如何保障一个由 AI 完成 80% 合并代码的软件开发生命周期。

核心数据：Anthropic 的代码库中约 80% 的合并代码由 AI 生成（Claude Code 驱动）。这给传统安全模型带来了全新挑战——传统的代码审查、安全扫描、合规流程都建立在「人写代码」的假设之上。当大部分代码由 AI 产出时，攻击面、审查带宽、供应链风险都发生了根本性变化。

文章从 Security Engineering 团队的角度，阐述了如何在 AI 原生 SDLC 中构建安全护栏：包括自动化安全验证管线、AI 生成代码的专项审计机制、以及如何在保持开发速度的同时确保安全合规。

这是继昨天的 Datadog/Temper 文章之后，Anthropic 官方博客连续推出的第二篇企业级 AI 工程实践深度文章，信号明确——Anthropic 正在用自身实践向业界展示「AI 原生软件开发」不只是写代码更快，而是整个工程体系（安全、质量、运维）都需要重新设计。

## Anthropic 正式发布 Agent Skills：Claude 的可加载技能系统【⭐⭐】（2025年10月首发，2026年6月更新）

**来源：** Anthropic News / Claude Blog
**链接：** https://claude.com/blog/skills
**关键词：** Agent Skills / Claude 技能系统 / 可组合 AI / 指令文件夹

### 摘要

Anthropic 正式介绍了 Claude 的 Agent Skills 系统。Skills 是包含指令、脚本和资源的文件夹，Claude 按需加载。只有当某项技能与当前任务相关时，Claude 才会访问它。

核心机制：
- Skills 是一种可组合的 AI 能力扩展方式——开发者将领域知识打包成文件夹（含 instructions、scripts、resources）
- Claude 在需要时才加载对应 Skill，避免上下文浪费
- 支持社区共享和自定义

这篇文章最初于 2025 年 10 月发布，最近于 2026 年 6 月 21 日更新。结合前几天 Datadog/Temper 的规范驱动开发理念和 GitHub Trending 上的 awesome-claude-skills（68.5k stars），可以看到 Agent Skills 正在成为 Claude 生态的核心扩展机制。

## Karpathy 分享 LLM 工作流技巧：Voice 漫谈法【⭐】

**来源：** Karpathy (Twitter/X)
**链接：** https://x.com/karpathy/status/2079610838143623371
**关键词：** Karpathy / LLM 使用技巧 / Voice 输入 / 工作流

### 摘要

Karpathy 在 Twitter 上分享了一个他觉得很有用的 LLM 工作模式——「长漫谈」（long ramble session）。

核心思路：有时候 LLM 需要更多信息才能理解你想做什么，但把想法全部打字写出来太累。他的方法是切到 Voice 模式，随口漫谈 10 分钟左右——完全不整理、想到哪说到哪、纯粹的意识流。有时他会事先声明「切到了语音识别，抱歉可能有错别字…」，有时会变成几轮小对话式的自问自答。

关键是：LLM 意外地擅长从不连贯的漫谈中重建出清晰的结构，输出的总结往往比自己原本混乱的想法干净得多。结果是「脑波同步」大幅提升，后续需要纠正的东西变少了。

这条推文获得 240 万浏览、2000+ 条回复，反映出 Voice 交互正在成为 LLM 工作流中越来越重要的输入模式。
