## Base44 将最复杂工程任务交给 Claude Fable 5：从"不敢碰"到"放心跑"【⭐⭐⭐】
**来源：** Claude Blog (Anthropic)
**链接：** https://claude.com/blog/working-at-the-frontier-why-base44-trusts-claude-fable-5-with-their-most-challenging-engineering-work
**关键词：** Claude Fable 5, Base44, vibe coding, 代码推理, 自主编程, 产品工程

### 摘要

Anthropic 发布了 Base44 的客户案例，展示了 Claude Fable 5 在真实产品工程中的能力边界。

**Base44 是什么：** 一个 vibe-coding 平台，让没有技术背景的用户也能构建全栈应用和网站。客户从小商家到 SaaS 公司都有。Yoav Orlev 是 Base44 第一名员工，现任产品负责人。

**核心发现——Fable 5 的推理能力突破：**
- Base44 从 2025 年初就开始用 Claude 模型驱动应用生成引擎，但之前的模型（包括 Sonnet 4）在处理多模块交叉依赖的核心任务时表现不够可靠
- 旧模型的典型问题：遇到错误时会在原地反复修改，而非意识到修复代码可能已存在于代码库其他位置
- Claude Fable 5 是第一个展现出"理解软件是如何被构建"的推理能力的模型——像一个高级工程师而非初级工程师的思维方式

**三个具体案例：**

1. **系统 Prompt 重构（原仅限最资深工程师）：** Fable 5 在约 1 小时问答后自主运行 4 小时，完成了 Base44 系统 prompt 及其数百种变体重构的 90-95%。团队当天下午就用 A/B 测试基础设施验证并上线。过程中模型还发现了一个 Base44 自家 eval 的盲区：他们没测试缓存命中率，而 prompt 改动在高并发下会导致缓存失效、推高成本。

2. **In-app Agent 底层框架修改：** Fable 5 遇到卡点时，推理出"这个问题很可能在代码库别处解决过"，主动跳转到相关模块查找修复方案并带回——这种跨模块的推理跳转在之前模型上没出现过。

3. **原生移动端开发环境搭建（产品经理操作）：** 一位 PM 用了约 2.5 小时就让 Fable 5 搭出了约 90% 完成度的原生移动开发环境。此前这类工作必须等最资深的 3 位工程师或移动端专家有空。

**模型评测方式：** Base44 对每个新 Claude 模型跑不同类型应用的 evals，测延迟、成本和构建错误率。他们还跑"造 Minecraft 克隆"这种极端测试看模型处理游戏物理和机制的能力。Fable 5 两个突出表现：极少的对话轮次完成任务 + 首次 prompt 就覆盖了边缘 case。

**团队工作流变化：** 以前只有高级工程师才能碰核心模块，现在 Fable 5 执行任务，Orlev 团队负责 review、测试、审批后上线。"Fable 给了我们做更大胆商业决策的信心，把产品带到了之前我们不敢碰的领域。"

**和 Anthropic 之前案例的横向对比：** 这个案例比之前发布的案例更具体地展示了 Fable 5 在"工程推理"层面的质变——不是写得快不快的问题，而是**能不能自主发现"应该去哪里找答案"**。之前 Sonnet 4 的用户反馈更集中在编码速度和准确性，而 Fable 5 的用户开始描述"像个有经验的人"。

## Google 为 Gemini Enterprise Agent Platform 引入 Parallel Web Search Grounding【⭐⭐】
**来源：** Google AI (Google Developers Blog)
**链接：** https://developers.googleblog.com/expanding-choice-in-gemini-enterprise-agent-platform-introducing-grounding-with-parallel-web-search/
**关键词：** Gemini, Enterprise Agent Platform, Grounding, Parallel Web Search, 企业AI

### 摘要

Google 在 Gemini Enterprise Agent Platform 中新增了 Parallel Web Search（并行网络搜索）作为 grounding 选项，扩展企业在构建 AI Agent 时的信息核实能力。

**Grounding 是什么：** 在企业级 AI Agent 场景中，grounding 指让模型的回答基于可验证的外部信息源（如网络搜索结果、企业知识库），而非仅依赖训练数据。这对于需要事实准确性、实时信息的企业应用（金融分析、市场情报、合规审查）至关重要。

**Parallel Web Search 的意义：**
- 并行执行多个搜索查询而非串行，大幅降低端到端延迟
- 更好的搜索覆盖率和结果多样性
- 在 Agent 需要交叉验证多个信息源时特别有效

**与 Claude 的对比：** Anthropic 也在推企业级 Agent，但更侧重模型本身的推理能力（如以上 Base44 案例）。Google 的差异化在于与 Google 搜索基础设施的深度整合，以及 GCP 生态内的企业数据连接能力。两条路线：Anthropic 走"模型推理够强，自己会查"，Google 走"搜索基建够强，帮模型查"。
