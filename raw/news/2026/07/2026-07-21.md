## Working at the frontier: How Rakuten builds agents overnight with Claude Fable 5【⭐⭐⭐】
**来源：** Claude Blog
**链接：** https://claude.com/blog/working-at-the-frontier-rakuten
**关键词：** Claude Fable 5、企业Agent、自我验证、长时间自主运行、Rakuten、taste alignment

### 摘要

Anthropic 发布了一篇 Enterprise AI 案例研究，介绍了日本乐天（Rakuten）如何使用 Claude Fable 5 构建能通宵自主运行的企业级 Agent。

核心人物是 Rakuten AI for Business 总经理 Yusuke Kaji，他从 2024 年 9 月就开始测试 Claude 各代模型。Rakuten 自 2025 年 3 月起大规模采用 Claude 加速软件开发（Claude Code）、跨业务部门部署 Agent、为百万级客户提供 AI 功能。公司内部推行"AInization"战略——将 AI 注入产品、销售、营销、财务等所有环节。

**Claude Fable 5 的三大关键突破：**

1. **自我验证（Self-verification）**：以前的模型如果在第一步走错方向，agent 很可能整个运行都白费，需要人到凌晨 2-3 点去纠错。Fable 5 能在运行中不断检查自己的工作，在出错前自己发现并纠正。

2. **回到第一性原理**：每一步都重新验证是否偏离原始意图，无需人工介入。Kaji 称之为"从 task 到 decision 的委托升级"——以前需要把工作拆成明确定义的 chunk 给 agent 执行，现在可以直接把整个任务交给它。

3. **Taste Alignment（品味对齐）**：Kaji 自创的术语。Fable 5 在模糊决策上的判断力与团队高度一致，即使只有最小化指导，也能做出符合团队审美的选择。

**实际效果：**
- Agent 在各领域解决问题速度约 10 倍提升
- 可在无人监督下运行数小时甚至通宵
- Agent 具备跨会话记忆：记住过去的错误，避免重复

**成本考量：** Kaji 坦率表示前沿模型价格是部署广度的决定因素。策略是按任务复杂度分层：Fable 5 跑"额外能力能改变结果"的任务，小模型处理其余工作。Fable 5 用更少 token 和更少错误路径完成任务，且几乎不需要人工引导，综合效率反而更高。

**下一步：** Kaji 正在探索让 agent 在人与人之间做协调——类似"经理"角色，弥合团队成员之间的上下文和品味差距。他认为社会还没找到 Fable 5 的"模型-任务匹配度"上限，"它已经跨过了那条线，来到了我们的世界。"

## Run Ray on TPU, Part 1: The foundations【⭐⭐】
**来源：** Google AI
**链接：** https://developers.googleblog.com/run-ray-on-tpu-part-1-the-foundations/
**关键词：** Ray 2.55、Google Cloud TPU、分布式计算、KubeRay、GKE、slice placement

### 摘要

Ray 2.55 版本正式引入了对 Google Cloud TPU 的一级官方支持（first-class support），开发者现在可以用熟悉的 Ray task-and-actor API 在 Google 加速器上运行分布式 Python 工作负载。

**核心技术挑战：** TPU 多主机"slice"需要通过芯片间互联（ICI, Inter-Chip Interconnect）保持严格的网络拓扑约束——同一个 slice 内的所有 TPU 必须同时调度、同时分配。传统调度器很难满足这种原子性要求。

**解决方案：** KubeRay Operator 在 GKE 上自动配置和标记底层硬件布局，Ray Core 通过新增的 `slice_placement_group()` 原语实现原子性预留完整 slice。开发者只需声明硬件拓扑（如 `"4x4"`），无需手写 placement 代码，即可通过 KubeRay、Ray Train 或 Ray Serve 部署任务。

这是系列文章第一篇（The foundations），聚焦基础设施层面的集成原理。对于正在评估 TPU 作为 GPU 替代方案、或已有 Ray 工作流想迁移到 TPU 的团队来说，这是一个重要的工程信号——Ray+TPU 的组合正在从"需要大量 hack"走向"开箱即用"。

## Apply for Anthropic's AI for Science rare disease research grants【⭐⭐】
**来源：** Anthropic News
**链接：** https://www.anthropic.com/news/rare-disease-research-grants
**关键词：** AI for Science、罕见病研究、Claude API、研究资助、Monarch Initiative、药物研发

### 摘要

Anthropic 宣布 AI for Science 项目的新一轮定向征集，主题聚焦罕见遗传病研究。这是继去年春季 AI for Science 项目启动后的首次专题化征集（thematic call）。

**资助方案：** 入选者可获得最高 $50,000 的 Claude API 额度，使用期限 6 个月，可使用 Claude Opus 等模型。申请截止日期为 2026 年 8 月 2 日 PST。

**两个赛道：**

1. **基础科研合作（Track 1）：** 面向临床研究者、患者组织和数据科学家，目标是加速罕见病机制发现。合作伙伴 Monarch Initiative 提供了关键基础设施——Mondo Disease Ontology（统一不同来源的疾病定义）、Monarch Knowledge Graph（跨物种基因型-表型数据整合）以及新发布的 DisMech 药物机制分类库。Claude 可以读取病例报告、变异数据库、注册模式等，以前所未有的速度和规模发现不同疾病之间的机制相似性。

2. **生物技术加速（Track 2）：** 面向早期 biotech，帮助加速罕见病药物研发。目前从确诊到治疗方案可用需要 1-2 年，大量时间花在排队等待、顺序化安全试验、手工准备数千页监管文件上。Anthropic 认为 Claude 可以大幅压缩文档准备工作（草拟和审核监管 dossier），加速治疗策略选择（分析靶点是否可药、跨疗法形式对比），以及通过寻找个体基因疗法之间的共享机制让多种疗法走"篮子试验"而非逐一申请 IND。

**已有案例：** Every Cure 用 Claude 筛选数百万候选药物的再利用机会；Centre for Population Genomics 构建 Claude 系统自动起草变异分类供专家审核；Violet Research Institute 用 Claude 跑生物信息学流水线、分析实验数据、起草监管文件。

这个项目值得关注的点在于：Anthropic 正在用"社区效应"思路做科学资助——让多个团队在同一主题下工作并互相交流技巧，效果优于孤立分配额度。Monarch 的 DisMech 是一个将 AI Agent 引入生物医学知识工程的有趣尝试。

## AlexsJones/llmfit — 一键检测你的硬件能跑哪些模型【⭐⭐⭐】
**来源：** Github Trending Daily
**链接：** https://github.com/AlexsJones/llmfit
**关键词：** 本地LLM、硬件兼容性检测、GGUF、MLX、Unsloth、Rust

### 摘要

llmfit 是今天 GitHub Trending 的榜首项目，一夜之间冲到近 30,000 星。解决的问题极其刚需：本地跑 LLM 最大的痛点不是模型选型，而是不知道自己机器到底能跑哪个。

放到更大的图景里看：本地 LLM 部署正在从"爱好者折腾"走向"工程化工具链"，llmfit + Ollama + LM Studio 这类组合让本地 AI 的门槛持续降低。近 30k 星也说明开发者对这个方向的需求有多强烈。

## dottxt-ai/outlines — LLM 结构化输出的事实标准库再爆发【⭐⭐】
**来源：** Github Trending Daily
**链接：** https://github.com/dottxt-ai/outlines
**关键词：** 结构化生成、JSON Schema、正则约束、CFG、LLM

### 摘要

outlines 是一个 Python 库，核心功能是让 LLM 严格按照给定的 schema、正则表达式或 CFG（上下文无关文法）生成输出——也就是"结构化生成"（structured generation）。14,653 星，在 LLM 可控生成领域是事实标准之一。

为什么现在又火起来？两个原因：一是企业级 LLM 部署对输出可靠性要求越来越高，"可能"出 JSON 不够，必须"一定"出符合 schema 的 JSON；二是 agent 系统中 tool calling 越来越普遍，模型生成的函数参数必须精确符合类型约束。outlines 通过编译时约束 token 选择空间来保证输出 100% 合规，比 prompt-based 的"请输出 JSON"可靠得多。

对比其他方案：guidance、lm-format-enforcer、SGLang 的 constrained decoding——outlines 的优势在于独立于推理框架、支持多种后端（transformers、llama.cpp、vLLM），这是它长盛不衰的关键。

## ayghri/i-have-adhd — 让 Coding Agent 不再"答非所问"的 Skill【⭐】
**来源：** Github Trending Daily
**链接：** https://github.com/ayghri/i-have-adhd
**关键词：** Agent Skill、Claude Code、ADHD友好、输出控制、开发者工具

### 摘要

一个轻量级 coding agent skill，核心功能很简单：让 agent 在输出时把答案直接放在最前面，而不是"埋在"大量上下文里。6,037 星，说明很多开发者都有同样的痛点。

i-have-adhd 作为 Claude Code plugin/skill，改变了 agent 的输出行为模式：先给答案（TL;DR），再展开细节。设计理念不复杂，但击中了 Agent UX 的核心问题——人类和 AI agent 的交互界面设计还远未成熟。

这个项目的走红反映了一个趋势：随着 coding agent 从"辅助"走向"主力"，开发者对 agent 的输出质量要求不再只是"正确"，还包括"可读性"和"效率"。6k 星的项目只有一个 skill 文件，说明社区对这类"小而美"的 agent 调优工具需求很大。
