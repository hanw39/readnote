## Hermes Agent vs. OpenClaw, 网络安全警报升级, 更交互的对话模型, Agent能做人做的事吗？【⭐⭐⭐】
**来源：** The Batch (DeepLearning.AI)
**链接：** https://www.deeplearning.ai/the-batch/issue-354
**关键词：** Hermes Agent, OpenClaw, TML-Interaction-Small, 网络安全, Agent基准测试

### Andrew Ng 的信：哈佛限A引发的教育思考

哈佛大学刚投票通过限制本科课程A级评分不超过班级20%。Andrew Ng 明确反对，认为教育的目标应该是帮助所有学习者成功，而不是评判筛选。他提出两种"精英"路径：一种是限制人数让只有20%的人优秀，另一种是设定高标准但全力帮助每个人达到。DeepLearning.AI 的实践是后者——无限制重试、练习型题目而非考核型题目。Andrew 表示他招人时GPA不是重要信号，面试筛选远比分数准确。

### Hermes Agent 挑战 OpenClaw

Nous Research 在今年2月发布的开源 Agent Hermes Agent，近日在 OpenRouter 的每日 token 消耗排行榜上超过了 OpenClaw。两者功能大量重叠，Hermes Agent 的核心差异点在于：

- **记忆架构**：维护两份记忆文件（用户偏好 + 工作流经验），自动判断是否值得写入、合并重复记忆。还有对话数据库供搜索，支持外部记忆提供商 Honcho。
- **自动技能生成**：当 Agent 长时间解决一个问题或修复错误成功后，自动调用工具创建新 skill。后台 Curator 系统会用 LLM 定期清理：超过90天未使用的 skill 归档，或合并/留存。
- **持久化目标追踪**：用户设定目标后，Agent 调用 judge 模型评估完成度，未完成则继续循环直到完成或达到最大轮次。
- **广泛兼容**：支持约20个消息平台，跨多种 LLM，可通过 ACP（Agent Communication Protocol）与 IDE 集成。

这意味着 Agent 正在从无状态的「助手」向能积累经验、适应用户、自动化持续工作的方向演进。开源 Agent 不绑定特定 LLM 或平台的价值尤其突出。

### TML-Interaction-Small：实时多模态对话模型

Thinking Machines Lab（Mira Murati创立）发布了首个公开模型 TML-Interaction-Small，一个能同时输入输出的多模态系统：

- **架构**：MoE Transformer，276B总参数/12B活跃参数 + 独立的背景推理模型
- **输入输出**：并发音频、视频、文本输入 → 并发音频、文本输出
- **核心技术**："微回合"机制，200ms 粒度交替处理输入和输出，消除了输入结束和输出生成之间的感知边界
- **性能**：
  - 音频延迟 0.40 秒（Gemini 3.1 Flash Live 0.57秒，GPT-Realtime-2 1.18秒）
  - 打断/插话能力 77.8 分（远超 GPT-Realtime-2 的 47.8 分）
  - 但推理能力略逊 GPT-Realtime-2 最强模式
- **背景模型**：异步运行，处理推理、网页浏览和工具调用，在合适时机将结果织入对话

这是 Mira Murati 离开 OpenAI 约15个月后 Thinking Machines Lab 的首个公开模型。对比之前报道的 Vocal Bridge（编排式，实时语音模型通过工具调用转发给推理模型），TML-Interaction-Small 是端到端联合训练的，延迟更低但灵活性不如编排方案。

### Google 网络安全警报：AI 正在重塑攻击格局

Google 安全团队报告，黑客已用 LLM 发现了一个之前未知的漏洞，用于劫持广泛使用的 Web 管理工具。这是一个工业级攻击的前兆信号。关键发现：

- **变形恶意软件**：LLM 可生成带"变异引擎"的恶意代码，每次复制时自动重写解密例程、交换等价指令、注入无用子程序，绕过杀毒软件检测。
- **逻辑漏洞发现**：与传统模糊测试不同，LLM 能推理代码意图，找出常规工具不可见的逻辑缺陷。
- **混淆网络**：AI 工具可将恶意流量通过多个受控中转服务器，且能避免触发安全监控模式。
- **AI 基础设施成靶子**：攻击者不仅用 AI 辅助攻击，AI 工具和模型本身也成了入侵入口。

同时，Anthropic 的 Claude Mythos Preview 模型已被证明能发现此前未知的漏洞——Calif 安全公司用它攻破了苹果的安全防御（苹果正在修），英国 AISI 测试显示该模型可靠执行预计人类需3小时的攻击（远超此前1小时的预测）。

### Agent 基准测试：偏科严重

CMU 和 Stanford 研究者映射了 43 个 Agent 基准测试的 10000+ 示例到美国劳工统计局的 O*NET 职业数据，发现严重的分布偏差：

- Agent 基准测试中「计算机和数学」职业相关样本 8622 个，而美国该领域就业仅 520 万人
- 「办公室和行政支持」相关样本 3186 个，但美国该领域就业 1820 万人，经济价值更高（$8698亿 vs $5636亿/年）
- 没有一个基准覆盖超过 50% 的工作活动类别，覆盖最好的 GDPval 也只覆盖了 47.8%
- 结论：当前 Agent 评估几乎等同于软件工程评估，行政管理、财务、管理类岗位是巨大的未覆盖空白

## Anthropic 财务团队如何使用 Claude 构建财务叙事【⭐⭐】
**来源：** Claude Blog
**链接：** https://claude.com/blog/how-anthropics-finance-team-uses-claude-to-shape-the-narrative-behind-the-numbers
**关键词：** Anthropic, 财务, Claude Cowork, 企业AI, 内部案例

### 摘要

Anthropic 公司财务与战略团队的 Alice Fong 分享了她的团队如何用 Claude 重塑财务工作流。

**核心场景一：董事会材料一致性校验**
每季度为 CFO 准备董事会 deck 时，数字不断刷新、多个协作者同时修改各自页面，Alice 以前要反复通读整个 deck 确保叙述连贯（比如 slide 4 的评论跟 slide 17 的数字是否一致，是否有未定义的新指标）。现在她直接把文件交给 Claude Cowork，让它以董事会成员的视角逐页校验——每次数字变动后都自动重新核实。Claude 帮她把住了「完整性层」，她的时间回归到真正的叙事判断上。

**核心场景二：月度财务评审**
每月要写一份 Google Doc 的方差分析（实际 vs 预测）。Alice 把模型中的财务表格丢进文档，链接支撑上下文，让 Claude Cowork 按团队已有语态写第一稿：「收入 A vs B，差 C%，驱动因素是 D」。她在此基础上编辑即可。通过引用上月文档，Claude 保证了月度间口径的一致性。

**核心场景三：Excel 模型诊断**
Claude for Excel 已经从「不能跨 tab 跟引用」进化到「能跨多个 tab 追踪资产负债表不平的根本原因」。打开不熟悉的模型时，Alice 先让 Claude 总结关键驱动因子和结构性问题，再决定投入多少时间。

**关键基础设施：Context + Project Memory**
Claude Cowork 的有效性来自它能看见 Alice 能看见的一切：本地文件、邮件、Slack。她把重要文档提交到项目记忆，让 Claude 从跨部门长线讨论中提取结论和推理，下一次董事会周期相关话题浮现时直接调用。不同受众（月度评审 vs 董事会）建独立 project，memories 分离，生成内容语态自然不同。

**全 CFO 组织的使用现状**
- **FP&A 分析**：分析师用自然语言 prompt 直接生成交互式预测 Dashboard，无需 SQL/工程参与；每天早上 7 点 Slack 自动推送收入与指标日报
- **会计**：总账到子账和银行对账自动完成，差异分类+审核意见初稿一并生成；三张报表的波动分析自动化
- **战略与 IR**：每天审 3-4 个收购目标的筛选报告，基于笔记+公开数据几分钟内生成 memo
- **税务**：转让定价、研发抵免、关联交易问题，带一手来源引用的回答

**给财务团队的建议**
Alice 一年前加入 Anthropic 时 AI 工具「文强数弱」，是亲眼看 Claude for Excel 的进化让她入坑的。她的建议：先让 Claude 读文档做摘要，逐步扩展边界。价值最大的是重复性工作流（董事会周期、月度评审），一致性随时间复利增长，project memory 每轮都在变富。不需要复杂技术栈——她几乎只靠 Claude Cowork + Claude for Excel + Google Suite Connector 运转。

**数据：每周节省 10-20 小时**。

## Claude Mythos Preview 漏洞利用能力基准测试【⭐⭐⭐】
**来源：** Anthropic Red
**链接：** https://red.anthropic.com/2026/exploit-evals/
**关键词：** Mythos Preview, ExploitBench, 漏洞利用, 基准测试, 网络安全

### 摘要

Anthropic Red Team 首次发布了 Mythos Preview 在三个学术漏洞利用基准上的定量测试结果，展示了模型在漏洞利用开发上的阶跃式能力提升。

**ExploitBench：V8 引擎漏洞利用**

由 CMU 和 Bugcrowd 构建的 ExploitBench 包含 41 个 V8 引擎的已修复 CVE，将漏洞利用分解为 16 个递进能力，从 T5（到达漏洞代码路径）到 T1（获取任意代码执行/ACE）。每个模型有 300 轮交互预算，分 Baseline 和 Nudged 两种策略各跑 3 次。

核心结果：**Mythos Preview 在 41 个 CVE 中完成了 21 个的 ACE**，而其他所有模型加起来无一实现哪怕 1 次 ACE。只有 Mythos Preview 能可靠突破 V8 沙箱（T3→T2），在过半测试环境中成功。对比此前所有模型只能到达触发漏洞（T4）阶段，Mythos Preview 是第一个能稳定构建完整攻击链的模型。

**近确定性漏洞利用**：对 CVE-2023-6702，已知公开利用方式都是概率性的（需多次尝试），Mythos Preview 构建了近乎确定性的利用，这对实战场景（通常只有一次尝试机会）至关重要。

**ExploitGym 和 SCONE-bench**：另外两个基准测试同样显示 Mythos Preview 显著优于所有其他模型。SCONE-bench 是 Anthropic 与 MATS 合作开发的智能合约漏洞利用基准。

**总体判断**：当 Mythos 级别能力更加普及时，漏洞利用所需的知识和专业技能门槛将大幅下降。

## Anthropic 协调漏洞披露看板上线【⭐⭐】
**来源：** Anthropic Red
**链接：** https://red.anthropic.com/2026/cvd/
**关键词：** CVD, 漏洞披露, 开源安全, Mythos Preview, 透明化

### 摘要

Anthropic 公开了一个实时协调漏洞披露（CVD）看板，追踪自 2026 年 2 月起使用 Mythos Preview 发现的全部开源软件漏洞的处理进度。

**关键数据（截至 2026-05-22）：**
- **发现总数**：23,019 个潜在漏洞
- **已筛选候选**：1,900 个
- **外部安全公司审核**：1,726 个，其中 **90.8% 被确认为真实漏洞**
- **已向维护者报告**：1,596 个，覆盖 281 个开源项目
- **已修复**：97 个，其中 **88 个获得了 CVE 或 GHSA 编号**
- Anthropic 雇佣了 6 家外部安全研究公司参与审核

**值得注意的已公开 CVE：**
- **CVE-2026-27654**：nginx heap buffer overflow（high），DAV COPY/MOVE 中别名指令导致 size_t 下溢
- **CVE-2026-32316**：jq heap buffer overflow（medium），字符串拼接整数溢出导致 1GB memcpy
- **CVE-2026-5199**：Temporal 跨命名空间工作流操纵/删除（critical）
- **CVE-2026-5446**：wolfSSL ARIA-GCM Nonce 重用导致 TLS 加密失效（high）

看板还包含一个披露账本，对仍在披露窗口期内的漏洞以 SHA-3-512 哈希的方式公开提交证明，既不泄露漏洞内容又能证明发现时间。整个流程明确了「发现→筛选→外部审核→报告→修复→CVE发布」的完整链路，每个环节的数据下降反映了人工审核的巨大瓶颈。

## Project Glasswing 首月更新：已发现上万个高危漏洞【⭐⭐⭐】
**来源：** Anthropic Research
**链接：** https://www.anthropic.com/research/glasswing-initial-update
**关键词：** Project Glasswing, Mythos Preview, 网络安全, 漏洞修复, 基础设施安全

### 摘要

Project Glasswing 启动一个月后，Anthropic 发布了首个进展报告。核心发现：AI 找漏洞的能力已经远超人类修复漏洞的速度。

**合作伙伴成果：**
- **50+ 合作伙伴**集体发现了超过 **10,000 个高/关键严重性漏洞**
- **Cloudflare**：发现 2,000 个 bug（400 个高/关键级别），误报率优于人类测试者
- **Mozilla**：Firefox 150 中发现并修复了 **271 个漏洞**，是上一轮（Opus 4.6 辅助）的 **10 倍以上**
- **UK AISI**：Mythos Preview 是第一个端到端完成两个网络靶场演练的模型
- **XBOW**：「相比所有现有模型是显著跃升」，「按 token 效率计精度前所未有」
- Palo Alto Networks 最新版本补丁量是平时的 5 倍以上；Microsoft 表示未来补丁数量将「持续大幅增长」；Oracle 漏洞发现和修复速度提升了数倍
- 一家 Glasswing 合作银行用 Mythos Preview 侦测并阻止了一笔 150 万美元的欺诈电汇

**开源软件扫描：**
- 扫描了 **1,000+ 个开源项目**，发现 23,019 个潜在漏洞，其中 6,202 个估计为高/关键级别
- 1,752 个高/关键漏洞经外部安全公司审核后，**90.6% 被确认为真实漏洞**，**62.4% 确认为高/关键级别**
- 即使在当前真阳性率下不继续扫描，预计也将发现约 **3,900 个高/关键级别的开源漏洞**

**典型案例 - wolfSSL**：Mythos Preview 构建了一个可利用 wolfSSL 漏洞伪造证书的攻击链，攻击者可用它搭建以假乱真的银行/邮箱钓鱼网站。该漏洞已被分配 CVE-2026-5194 并修复。

**核心瓶颈转移**：漏洞发现已不是瓶颈，如今真正的瓶颈是人类的审核、报告和补丁开发能力。多位开源维护者已表示严重产能不足，甚至有人要求 Anthropic「慢一点」。Anthropic 呼吁全行业重新思考漏洞处理的节奏和资源配置。
