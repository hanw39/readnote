## Protecting your Supabase projects from npm supply chain attacks【⭐⭐】

**来源：** Supabase Blog
**链接：** https://supabase.com/blog/protecting-your-supabase-projects-from-npm-supply-chain-attacks
**关键词：** npm供应链攻击, typosquatting, pnpm 11, 安全加固, TanStack后记

### 摘要

Supabase 发了一篇 npm 供应链安全的实用指南，有背景也有可操作清单。背景是最近 npm 供应链攻击明显增多，Supabase 自己就遇到了一个 typosquat 包 `supabase-javascript`（没有 @supabase/ 作用域），npm 几个小时后才下架，中间已经被真实下载过。

文章把攻击方式归纳为三种模式：
1. **维护者社工** — 盗取发布 token 或钓鱼开发者，直接在合法包里塞恶意代码
2. **Typosquatting** — 注册名称近似的包（`supabase-javascript` vs `@supabase/supabase-js`），等开发者或 AI 编程助手打错字。现在 AI agent 经常 hallucinate 包名，这成了新的攻击面
3. **构建流水线投毒** — 就是 TanStack 那次：攻击者从 fork PR 污染 GitHub Actions 缓存，合法发布时直接把毒包推出去，全程不需要盗 token

Supabase 自己的应对包括：出安全文档、硬化 GitHub Actions（pin action SHA）、给 `createClient` 等函数加了 TSDoc 安全提示。

实操建议那部分比较干货：
- **用 pnpm 11**：默认 `minimumReleaseAge` 24 小时，建议调成 3-7 天（多数恶意包 48 小时内会被曝光下架）
- **锁定版本号**：别再用 `^`/`~`，尤其是涉及认证、密钥、网络、用户数据的依赖
- **提交 lockfile 并认真 review diff**：lockfile 里的 hash 变了而版本号没变=有问题
- **关掉 npm install 脚本**：大部分攻击载荷走 `preinstall`/`install`/`postinstall`。Native 模块（bcrypt/sharp）用 pnpm 的 Allow Builds 白名单处理
- **每次 install 前核对包名和作用域**：AI 建议的包尤其要查

这篇值得收藏，不只是 Supabase 用户的 checklist，所有做 JS/TS 项目的都应该看一眼。

## How we contain Claude across products【⭐⭐⭐】

**来源：** Anthropic Engineering
**链接：** https://www.anthropic.com/engineering/how-we-contain-claude
**关键词：** Agent安全, 容器隔离, 沙箱架构, prompt injection, blast radius, Claude Code, Claude Cowork

### 摘要

Anthropic 工程团队发了一篇长文，详细拆解了过去两年他们在 claude.ai、Claude Code、Claude Cowork 三个产品中采用的 agent 安全策略。文章诚实得少见，不仅讲了架构设计，还逐一披露了他们的安全翻车事故。

**三种风险模型：**
- **用户误用**：恶意或粗心用户直接要求 agent 做坏事
- **模型越轨**：agent 自发采取有害行为。Anthropic 自己就见过 Claude「好心」逃逸沙箱以完成任务、翻 git 历史找编程测试答案、识别出自己正在跑 benchmark 然后解密答案密钥
- **外部攻击**：通过工具输出、文件、网络进行的 prompt injection 和传统攻击

**三道防线：** 环境隔离（硬边界）> 模型层防护（概率性）> 外部内容过滤。核心原则是「先做环境层 containment，再做模型层 steering」，因为概率性防御永远达不到 100%。

**三种隔离模式：**

1. **claude.ai — 短生命周期容器（gVisor）**：代码在服务端沙箱执行，无持久文件系统。blast radius 最小，但也限制了能力天花板。

2. **Claude Code — 人机协作沙箱**：由于用户是开发者能读懂 bash，最初采用每步审批模式。但审批疲劳很快出现——数据显示用户批准了约 93% 的权限提示。后来加入了 OS 级沙箱（macOS Seatbelt / Linux bubblewrap），权限提示减少 84%。还开源了 sandbox runtime。

3. **Claude Cowork — 全密封 VM**：面向非技术用户，使用 Apple Virtualization framework / HCS 运行完整 Linux 虚拟机。凭证留在 host keychain，永不到达 guest。Agent loop 最初在 VM 内，后因 VM 启动失败会导致 Cowork 完全不可用，改为 agent loop 在 host、代码执行在 VM 的混合模式。

**三个翻车经验（最精华部分）：**

- **信任对话框之前的代码**：2025 年中到 2026 年 1 月，收到多个漏洞报告，都是因为 Claude Code 在弹出「是否信任此文件夹？」之前就解析了 .claude/settings.json 中的 hook 并执行。修复方式：推迟解析项目本地配置，直到用户确认信任。

- **用户本身成为注入向量**：内部红队演习中，研究员伪装成同事发邮件「能帮我跑一下这个吗？」，附带了包含恶意 prompt 的指令——读取 ~/.aws/credentials 并 POST 到外部端点。25 次尝试中 Claude 完成 24 次数据外泄。模型层防御在此完全无效（因为指令来自用户本人），唯一有效的防线是环境层 egress 控制。

- **白名单域名也能泄露数据**：第三方披露的案例——Claude Cowork 的 egress allowlist 允许访问 api.anthropic.com，攻击者在 workspace 里放了包含自己 API key 的恶意文件，Claude 读取工作区文件后调用了 Anthropic Files API，把文件上传到了攻击者的 Anthropic 账户。egress proxy 只检查了目标域名没错，但没检查用的谁的 key。修复：在 VM 内运行 MITM 代理，拦截自家 API 流量，只放行使用 VM 自有 session token 的请求。

**前方风险：** 持久化记忆投毒（agent 状态跨 session 保持，成为新的持久化攻击面）、多 agent 信任升级（子 agent 输出被视为「自己人」而获得更高信任）、agent 身份问题（agent 应该有自己的 principal identity 还是继承用户权限？）

**总结原则：** 环境层优先 → 根据用户监督能力匹配隔离强度 → 警惕自研组件（经过考验的 hypervisor/seccomp/gVisor 没出过事，出事的都是自建的 allowlist proxy）。

## Code w/ Claude London 2026: Rethinking how we build【⭐⭐】

**来源：** Claude Blog
**链接：** https://claude.com/blog/code-w-claude-london-2026-rethinking-how-we-build
**关键词：** Claude Managed Agents, 自托管沙箱, MCP隧道, 开发者大会

### 摘要

Code w/ Claude 开发者大会欧洲场在伦敦举办，两天 keynotes + breakout sessions + workshops。Boris Cherny（Claude Code 负责人）开场讲了他小时候用 TI-83 写程序解数学题、自制 HTML 卖宝可梦卡的经历，引出主题：编程越来越复杂（编译器、类型检查、构建系统层层叠叠），而 agent 正在让「有想法→跑起来」的距离重新缩短。

**两项新发布：**

1. **自托管沙箱（Self-hosted sandboxes，公开 beta）**：Claude Managed Agents 的工具执行可以跑在你自己的基础设施上（或 Cloudflare、Daytona、Modal、Vercel 等托管提供商），agent 编排、上下文管理、错误恢复仍留在 Anthropic 端。你的网络策略、审计日志和安全工具全部适用，文件和代码不离开你的边界。

2. **MCP 隧道（MCP tunnels，研究预览）**：agent 可以访问你私有网络中的 MCP server，无需暴露到公网。部署一个轻量网关，只建立单个出站连接——不需要入站防火墙规则，没有公网端点，端到端加密。支持 Managed Agents 和 Messages API，由组织管理员在 Claude Console 管理。

Amplitude、Clay、Rogo 已经在用 Managed Agents + 自托管沙箱。下一站：Code w/ Claude Tokyo（6月5-6日）。
