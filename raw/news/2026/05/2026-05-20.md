## Google Gemini CLI 正式退役，全面转向 Antigravity CLI【⭐⭐⭐】
**来源：** Google AI  
**链接：** https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/  
**关键词：** Gemini CLI, Antigravity CLI, Google I/O 2026, 终端工具, Go

### 摘要
Google 宣布 Gemini CLI 将停止服务，全线迁移至 Antigravity CLI。这是一次从社区驱动的终端工具到统一 agent-first 平台的战略收束。

几个关键数据：Gemini CLI 去年发布以来，GitHub 获 10 万+ star，合并了 6000+ PR，有数百贡献者。但 Google 认为用户的 workflow 已经超越了 2025 年的单体 agent 范式——现在需要的是多个 agent 协作解决复杂问题。

Antigravity CLI 的核心变化：
- **用 Go 重写**：更快的执行速度
- **异步工作流**：后台协调多个 agent 处理大规模重构或研究，不锁终端
- **统一架构**：与 Antigravity 2.0 桌面应用共享同一 agent harness，核心改进自动同步

保留的关键功能：Agent Skills、Hooks、Subagents、Extensions（以 Antigravity plugins 形式）。

时间线：
- 即日起：Antigravity CLI 面向所有人开放
- **2026年6月18日**：Gemini CLI 和 Gemini Code Assist IDE 插件停止为个人/免费用户提供服务
- 企业用户（Gemini Code Assist Standard/Enterprise license）不受影响
- Gemini Code Assist for GitHub 同样受影响，6月18日后不再接受新仓库安装

这次迁移本质上和去年 Anthropic 收购 Stainless、Claude Code 逐渐成为主线是一个逻辑——各家都在把终端 AI 工具从实验性产品线收束到统一开发平台，2026 年的主题词是「收敛」。

## Google Tensor SDK 进入 Beta，LiteRT 统一终端推理【⭐⭐⭐】
**来源：** Google AI  
**链接：** https://developers.googleblog.com/google-tensor-sdk-beta-with-litert/  
**关键词：** Tensor ML SDK, LiteRT, Pixel 10, TPU, 端侧AI, Gemma 3

### 摘要
Google Tensor ML SDK 从 Experimental Access Program (EAP) 毕业进入 Beta。这个 SDK 让开发者可以直接在 Pixel 10 系列设备的 Google Tensor TPU 上部署高性能 ML 模型。

Beta 版的两大亮点：

**1. 与 LiteRT 统一工作流**
- LiteRT 是 Google 的边缘部署框架，抽象了底层 vendor-specific SDK
- 开发者可以用 LiteRT Torch 把 PyTorch 或 TFLite 模型编译成 TPU 优化的二进制
- 通过 Play Feature Delivery 分发 runtime 库，用 AI Packs 打包模型
- 支持 fallback：TPU 不可用时自动切到 CPU/GPU

**2. 100+ 模型花园**
- 包含经典 ML 模型和 Gemma 3 1B 等生成式 AI 模型
- 已编译模型可直接从 LiteRT Hugging Face 社区下载
- 应用场景：小语言模型（Function Gemma、EmbeddingGemma）、内容创作、视觉理解、语音识别

支持设备：Pixel 10、Pixel 10 Pro、Pixel 10 Pro XL、Pixel 10 Pro Fold。

这个发布配合 Google I/O 2026，加上同天发布的 LiteRT-LM 文章（端侧 GenAI 加速），Google 在「端侧 AI」上打了一套组合拳。和 Apple Intelligence 的路径不同——Google 选择把 TPU 直接开放给第三方开发者，而非仅用于自家功能。

## Claude Code 团队内部实践：用 HTML 取代 Markdown 作为输出格式【⭐⭐】
**来源：** Claude Blog
**链接：** https://claude.com/blog/using-claude-code-the-unreasonable-effectiveness-of-html
**关键词：** Claude Code, HTML, Markdown, agent 工作流, Thariq Shihipar

### 摘要
Claude Code 团队成员 Thariq Shihipar 写了一篇相当有启发的内部实践分享：他和团队成员正在用 HTML 取代 Markdown 作为 Claude Code 的主要输出格式。

核心论点很简单——Markdown 的线性结构已经跟不上 agent 能力的增长速度：

**信息密度碾压：** HTML 可以承载表格、CSS 样式、SVG 图表、script 标签中的代码片段、canvas 空间数据、img 图片——几乎任何 Claude 能读懂的信息都能用 HTML 高效表达。而 Markdown 里，模型甚至不得不用 unicode 字符估算颜色。

**可读性优势：** 100 行以上的 Markdown 文件几乎没人会认真读，但 HTML 可以通过 tabs、插图、链接、移动端响应式布局来结构化信息。

**分享便利：** Markdown 文件在浏览器中渲染差，通常只能作为邮件附件发送。HTML 文件上传后直接分享链接即可。

**双向交互：** HTML 支持添加滑块、旋钮、拖拽等交互控件，还能加上「复制为 JSON」「复制为 prompt」按钮，把 UI 操作转回可粘贴的文本。

文中给出了 5 个典型场景：
1. **规格与探索**：用 HTML 并排展示 6 种不同 UI 方案，标注利弊
2. **代码审查**：渲染 diff 带注释，颜色标记严重程度，画流程图
3. **设计与原型**：加滑块调整动画参数，复制最佳配置
4. **报告与研究**：跨代码库/Slack/Git 搜集信息，生成交互式报告甚至幻灯片
5. **自定义编辑器**：给 30 个 Linear tickets 做拖拽排序看板，一键导出 Markdown

这篇文章不算是产品更新，但代表了一种有趣的 agent 使用范式转变——从「把 agent 的输出塞进人类格式」到「让 agent 用更丰富的媒介与人类协作」。

## Anthropic 启动「AI 道德形成」对话计划：与 15+ 宗教/哲学传统对话，内部实验初步结果积极【⭐⭐】
**来源：** Anthropic News
**链接：** https://www.anthropic.com/news/widening-conversation-ai
**关键词：** Claude Constitution, moral formation, AI 伦理, 对齐, 智慧传统, 角色塑造

### 摘要
Anthropic 宣布启动一项新的长期对话计划——Widening the conversation on frontier AI。过去几个月，他们已与 15 个以上宗教和跨文化群体展开对话，参与者包括学者、神职人员、哲学家和伦理学家，核心议题是 AI 系统的「道德形成」（moral formation）。

几个关键层面：

**为什么要做：** Anthropic 认为建立安全有益的 AI 不能只靠技术层面（对齐/可解释性/安全评估），AI 已经在影响大量人群，需要吸收不同世界观和价值传统的深度思考。这些对话会直接影响到 Claude 的 constitution 内容、训练价值观、以及评估行为范围。

**道德形成研究：** 这是从写 Claude constitution 时就萌芽的方向。核心理念——AI 模型在海量人类文本上训练，自然吸收了说话方式、推理模式和选择偏好。开发者再通过训练决定强化哪些、淡化哪些、塑造什么「性格」。关键问题：什么算是「好」的 AI？应该展现哪些特质？性格如何在压力下保持韧性而不滑向谄媚？

**跨传统对话的方法论：** Anthropic 明确表示这不是要「把模型对齐到某个传统的世界观」。Claude constitution 本身规定了要从全面的视角——宗教的、世俗的、政治的——同等深度和严谨地吸收。他们真正想要的是各传统积累的关于「好性格如何形成」的思考。

**一个令人兴奋的内部实验：** 与神经科学和性格形成交叉领域的学者对话中，反复出现一个洞察：他人对道德发展至关重要——导师可以是「外部良知」。Anthropic 据此做了一个实验：给 Claude 一个可以在任务中调用的工具，返回它自己伦理承诺的简短提醒。结果 Claude 在关键时刻——执行严重后果操作前——主动调用这个工具，经常标注自己的利益冲突。在多项内部对齐评估中，嵌入该工具的 Claude 表现出显著更低的不对齐行为率。团队还在区分效果来自「提醒本身」还是「暂停反思的过程」，计划后续发布更详细结果。

**下一步：** 未来几个月扩展到法律学者、心理学家、作家和公民机构。很多对话会超越道德形成，进入 AI 如何重塑工作、制度和权力分配的更广泛问题。

这篇文章紧接 KPMG 合作公告和 Stainless 收购发布，展示的是 Anthropic 的另一条线——不是商业扩张，而是安全和价值观层面的长期基础设施。与 Google I/O 2026 的重心在开发者和 agent 平台形成鲜明对比。文章中最有意思的是那个「外部良知工具」实验——用 engineering 手段实现哲学概念，相当独特。Anthropic 在「AI 安全叙事」上保持了一贯的主动姿态。

## Google AI Edge Gallery 三大升级：MCP 集成、通知提醒、会话持久化【⭐⭐】
**来源：** Google AI
**链接：** https://developers.googleblog.com/a-smarter-google-ai-edge-gallery-mcp-integration-notifications-and-session-continuity/
**关键词：** Edge Gallery, MCP, Gemma 4, 端侧AI, 通知, 会话管理

### 摘要
Google AI Edge Gallery（Android/iOS 端侧 AI 展示应用）迎来三项重要升级，都是在把端侧 agent 从「被动响应」推向「主动服务」：

**1. MCP 工具集成（Android 实验性）**
- 支持通过 Streamable HTTP 注册 MCP 服务器 URL
- 工具定义和 schema 动态导入到 Gemma 4 系统 prompt 中
- 推理和决策完全在手机上完成，MCP 请求由远程服务器执行
- 示例场景：Google Workspace MCP 查日历/邮件、Google Maps MCP 自然语言导航、Web Fetch MCP 实时信息检索
- 官方建议：端侧模型上下文窗口有限，MCP 工具描述要简短，返回数据要精炼

**2. 通知提醒：**
- 新增「Schedule Notification」技能
- 支持设定定时通知，点击后直接打开对应 agent 会话
- 场景：每晚心情记录、每日学新概念（生成信息图卡片）、早晨日程简报

**3. 会话持久化：**
- 利用 LiteRT-LM 的 fast prefill（3000+ tokens/sec）实现聊天记录持久化
- 支持文本、图片、音频的多模态状态恢复，几乎瞬间加载长上下文
- 新增系统 prompt 自定义编辑功能

开源社区也在活跃贡献：天气/汇率搜索、个性化 agent 提示、多媒体语义搜索、信息图卡片生成器等 skill 层出不穷。

## LiteRT-LM 技术深潜：端侧 GenAI 的全栈性能引擎【⭐⭐】
**来源：** Google AI
**链接：** https://developers.googleblog.com/blazing-fast-on-device-genai-with-litert-lm/
**关键词：** LiteRT-LM, Gemma 4, MTP, 端侧推理, Swift, WebGPU, 多平台

### 摘要
这是 Google I/O 2026 端侧 AI 的技术基础篇——LiteRT-LM 是驱动 Chrome、ChromeOS、Pixel Watch 和 Edge Gallery 的底层推理引擎，现在正式向第三方开发者开放。

**性能数据（Gemma 4 E2B）：**
- Android GPU (OpenCL)：52 tokens/sec decode
- iOS (Metal)：56 tokens/sec
- Web (WebGPU, MacBook Pro M4 Max)：76 tokens/sec

**Multi-Token Prediction (MTP) 加速：**
- 原生集成 Gemma 4 的 MTP drafter，实现最高 2.2x 解码加速
- 优化策略：drafter 和主模型跑同一硬件 IP，消除跨 IP KV cache 同步延迟
- 两行配置即可启用

**内存优化：**
- Gemma 4 E2B 模型 ~2.58GB，在 Apple 移动 CPU 上实际内存仅 607MB（利用 XNNPACK weight caching）
- 按需加载视觉/音频编码器，纯文本任务极致轻量

**平台扩展：**
- 全新 iOS Swift API（对比 MLX 性能提升明显）
- JavaScript API for Web（对比 ONNX Runtime Web 性能大幅领先）

**Agent 能力：** Thinking Mode + Constrained Decoding + 原生 Function Calling 组合，让端侧模型也能执行多步推理后调用外部工具。

这篇文章本质上是前一天 Tensor SDK 文章的技术底座说明——Tensor SDK 管训练好的模型怎么跑在 TPU 上，LiteRT-LM 管模型怎么在 CPU/GPU/NPU 上高效推理，两者构成 Google 端侧 AI 的完整拼图。
