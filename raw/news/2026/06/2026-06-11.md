## [[模型与技术]]

### DiffusionGemma发布：Google DeepMind推出扩散式文本生成模型【⭐⭐⭐】
**来源：** Google AI
**链接：** https://developers.googleblog.com/diffusiongemma-the-developer-guide/
**关键词：** DiffusionGemma, Google DeepMind, 扩散模型, 非自回归生成, Gemma 4, vLLM, 并行生成

#### 摘要

Google DeepMind 正式发布 DiffusionGemma 开发者指南，这是基于 Gemma 4 骨干网络构建的实验性扩散文本生成模型，代表着从传统自回归（逐token生成）到扩散式并行生成的范式转变。

**核心架构创新：**

- **统一状态扩散（Uniform State Diffusion）**：不以逐个token预测方式工作，而是从一个填充随机占位符的 256-token "画布"开始，通过多次迭代去噪（denoising）并行优化所有位置。高置信度token帮助解析相邻位置，使整个序列在迭代中逐步"聚焦"成型。
- **块自回归扩散（Block Autoregressive Diffusion）**：对于超过256 token的长序列，每完成一个256-token块的去噪后，将其提交到KV缓存，然后基于已提交的历史初始化新画布继续生成。这种设计结合了并行块的生成速度与自回归模型的序列稳定性。
- **双向注意力与自我纠错**：与只能"向后看"的自回归模型不同，Denoiser的双向注意力让画布上的每个token都能关注所有其他token。如果在去噪过程中某个token置信度下降，采样器可以对其重新加噪并替换——这是自回归模型完全不具备的自我纠错能力。

**性能数据：**

- 模型为 26B MoE（混合专家），推理时仅激活 3.8B 参数，量化后可部署在 18GB VRAM 限制内
- 在 NVIDIA GeForce RTX 5090 上达到 700+ tokens/秒，单个 NVIDIA H100 上超 1000 tokens/秒
- 相比传统自回归模型有最高 4 倍生成速度提升

**开发者生态：**

- 已集成 vLLM，支持 OpenAI 兼容 API 本地部署
- 同时支持 HuggingFace Transformers、SGLang、MLX
- 发布 Hackable Diffusion 训练工具箱，包含数独求解器微调配方
- 微调后数独正确率从 0% 提升到 80%，推理步数反而减少
- 权重 Apache 2.0 许可，已在 HuggingFace 开放下载

**点评：** 这是文本生成领域一次真正的架构创新。扩散模型在图像/视频生成中已证明其价值，如今 Google 将其带入文本生成，并拿出了具体的工程方案和性能数据。关键看点是这种非自回归方法在实际文本生成质量上能否匹敌或超越自回归模型——目前仅发布实验性版本，生产可用性还需观察。

### Claude Managed Agents：Anthropic 正式发布生产级 Agent 托管平台【⭐⭐⭐】
**来源：** Claude Blog
**链接：** https://claude.com/blog/building-with-claude-managed-agents
**关键词：** Claude Managed Agents, Anthropic, Agent 托管, 生产级, 安全沙箱, Vault, Dreaming, MCP tunnels

#### 摘要

Anthropic Applied AI 团队发布 Claude Managed Agents 架构深度介绍——这是一套可组合的 API，用于构建和部署生产级 Agent。核心洞察：**基础设施才是原型与生产之间的真正鸿沟**，团队往往在安全、状态管理、权限、harness 调优上耗费大量开发周期。

**架构演进路线：**
- 2023：简单 API（tokens in, tokens out），单轮交互
- 2025：Claude Code 内置 agent harness（loop、工具执行、subagent、上下文管理）
- Claude Agent SDK：将 Claude Code 的 harness 开放给开发者
- Claude Managed Agents：将 harness 和生产基础设施一起托管

**核心设计——"大脑与双手解耦"：**
- Harness（调用 Claude）与代码执行沙箱分离运行
- Session 是追加式事件日志：每次模型调用、工具调用、结果都被记录
- Claude 可以在容器启动前就开始推理，容器只在需要执行工具时才就用
- 效果：TTFT（首 token 时间）中位数降低约 60%，p95 降低超 90%

**三大原语：**
1. **Agent**：配置（模型、提示词、工具集、护栏）
2. **Environment**：执行上下文（沙箱容器、网络规则、预装包），可选 Anthropic 托管或自托管
3. **Session**：每次运行配对 Agent + Environment，独立沙箱实例，完整事件历史持久化服务端

**关键能力：**
- **Vaults**：凭证与沙箱物理隔离，envelope encryption 加密存储，代理按需解密取用，防止 prompt injection 泄露 token
- **Persistent Sessions**：长时间运行可暂停/恢复，checkpoint 容器状态，session 事件流即 observability
- **Dreaming**：定时任务审查 agent session 和记忆库，提取模式、整理记忆，让 agent 随时间改进——从持续性 session 日志中学习
- **Self-hosted Sandboxes**：代码执行可在客户 VPC 内，配合 MCP tunnels 连接私有网络内的 MCP 服务器
- **Outcomes**：agent 可对自身工作按评分标准自评

**生产案例：**
- **Notion**：Custom Agents 运行在 Managed Agents 上，任务板上分配给 Claude，早期原型将约 12 小时工作压缩到 20 分钟
- **Rakuten**：跨产品/销售/市场/金融部署专家 agent，每个约一周上线
- **Sentry**：Seer 调试 agent 与 Claude agent 配对（写 patch + 开 PR），由单人工程师数周内完成
- **Asana / Atlassian**：AI Teammates 和 Jira workflow developer agents

**harness 随模型进化的价值：** Anthropic 分享了一个具体案例——Sonnet 4.5 时代 agent 会在接近上下文限制时"焦虑"并仓促完成（context anxiety），团队通过 context reset 修复；但 Opus 4.5 上该行为消失，之前的修复反而变成额外开销。这说明了为何需要托管 harness：harness 应与模型协同演进，而不应成为团队维护负担。

**点评：** 这是 Anthropic 在 Agent 基础设施领域最系统的战略阐述。Managed Agents 本质是将 Claude Code 积累的 agent 工程经验沉淀为平台能力，目标客户是那些不想自建 agent harness 的企业。"大脑与双手解耦"的架构选择是技术亮点——将安全边界、延迟优化、可观测性三个难题通过架构设计同时解决。对标的竞品是 OpenAI 的 Agents SDK / Responses API。

## 今日趋势观察

**1. 扩散模型进入文本生成领域**：DiffusionGemma 是今日最重磅的发布。如果扩散式文本生成在质量上能达到自回归模型的水平，整个 LLM serving 的性能范式将被改写。Google 选择从 26B MoE 实验性切入是务实策略——先在中等规模验证，再考虑扩展。

**2. Agent Skills 标准化加速**：Google（google/skills）、Addy Osmani（agent-skills）、obra（superpowers）三个项目同时登上 GitHub Trending，显示行业正在激烈竞争 agent skills 的标准格式。谁能成为"agent skills 的 Docker Hub"？

**3. AI 编码工具的透明化**：system-prompts 项目 14 万星说明开发者对 AI 工具运作机制的强烈好奇心。各大公司被迫在"保密"和"开发者信任"之间寻找平衡。

**4. Rust 在 AI 基础设施中崛起**：Goose（Rust）、RuView（Rust）、turbovec（Rust）三个 AI 相关项目都用 Rust 编写。性能敏感场景下 Rust 的采用率持续上升。

**5. Agent 托管平台成为大厂必争之地**：Anthropic 正式推出 Claude Managed Agents，将 Claude Code 积累的 agent harness 经验平台化。"大脑与双手解耦"的架构（harness 与沙箱分离）成为解决安全、延迟、可观测性三大难题的新范式。与 Google 的 google/skills、OpenAI Agents SDK 形成三足鼎立之势——Agent 基础设施层的竞争正在从"谁有 SDK"升级到"谁能提供端到端生产托管"。
