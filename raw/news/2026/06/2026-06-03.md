## Claude Code 动态工作流：为每个任务定制编排引擎【⭐⭐⭐】

**来源：** Claude Blog
**链接：** https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code
**关键词：** Dynamic Workflows、Multi-agent、子代理编排、并行执行、对抗验证、Claude Code

### 摘要

Anthropic 上周在 Claude Code 中发布了 **Dynamic Workflows（动态工作流）**——Claude 现在可以在运行时编写自己的 JavaScript 编排脚本（harness），按任务需求动态协调多个子代理。这篇文章由 Anthropic 团队成员 Thariq Shihipar 和 Sid Bidasaria 撰写，详细介绍了工作流的动机、模式和最佳实践。

**为什么需要动态工作流：**
默认的 Claude Code 在单一上下文窗口中既规划又执行。这对多数编码任务有效，但在长时运行、大规模并行、高度结构化或对抗性任务中会暴露三个失败模式：

1. **代理懒惰（Agentic laziness）**：Claude 在复杂多步骤任务中提前停止，比如安全审计做了 35/50 项就宣称完成
2. **自我偏好偏差（Self-preferential bias）**：倾向于偏好自己的结果，尤其在自我验证时
3. **目标漂移（Goal drift）**：多轮对话和上下文压缩后，边缘需求或"不要做X"等约束逐渐丢失

工作流通过为每个子代理分配独立上下文窗口和聚焦目标来对抗这些问题。

**动态 vs 静态工作流：**
之前的 Agent SDK 和 claude -p 可以创建静态工作流，但静态流程要覆盖所有边界情况，通常比较泛化。Opus 4.8 加上动态工作流后，Claude 能针对你的具体场景量身定制编排脚本。

**六种核心模式：**

1. **分类派发（Classify-and-act）**：分类代理判断任务类型 → 路由到不同的处理代理
2. **扇出合成（Fan-out-and-synthesize）**：大任务拆成小步骤 → 并行执行 → 汇总合成。合成步骤是屏障点，等待所有扇出代理完成后合并结构化输出
3. **对抗验证（Adversarial verification）**：为每个执行代理配备独立的验证代理，按评分标准对抗性审查输出
4. **生成过滤（Generate-and-filter）**：批量生成方案 → 按评价标准过滤 → 去重 → 只返回最高质量的结果
5. **锦标赛（Tournament）**：N 个代理用不同方案竞争同一任务 → 评判代理两两对比 → 选出优胜者。文章指出对比判断比绝对打分更可靠
6. **循环至完成（Loop until done）**：工作总量不确定时，循环生成代理直到停止条件满足

**实际应用场景：**

- **迁移和重构**：Bun 从 Zig 重写到 Rust 就用了工作流。秘诀：把任务拆成步骤（调用点、失败测试、模块等），每个修复派一个子代理在独立 worktree 中执行，再由对抗代理审查后合并
- **深度研究**：Claude Code 内置的 /deep-research 技能就是工作流驱动的——扇出网页搜索 → 获取源 → 对抗性验证声明 → 合成引证报告。也可以对 Slack 上下文、代码库探索等做类似研究
- **深度验证**：识别所有事实主张 → 每个主张派子代理验证 → 验证代理再检查源质量
- **排序**：对 1000+ 行项目做定性排序时，单一 prompt 质量会下降。改用锦标赛（两两对比代理）或分桶并行排序
- **规则遵守**：把 CLAUDE.md 中常被忽略的规则拆成独立验证代理（每条规则一个），并让一个怀疑者代理审查规则本身以避免误报
- **排查根因**：从日志、文件、数据中分别提取证据生成独立假设 → 每个假设面对一组验证和反驳代理。不限于代码，也适用于销售下滑分析、数据管道故障等
- **大规模分流**：分类代理对 backlog 分类 → 去重 → 可以尝试修复或升级给人。关键模式是"隔离（quarantine）"——读取不可信公共内容的代理不能执行高权限操作。配合 /loop 实现持续分流
- **探索和品味判断**：UI 设计、命名等需要品味的问题，让审查代理按评分标准筛选方案，打分满意才停止
- **轻量评估**：在独立 worktree 中生成输出 → 对比代理按标准比较并打分
- **模型和智能路由**：分类代理先调研任务复杂度，再决定用 Sonnet 还是 Opus

**什么时候不用工作流：**
文章明确警告——工作流消耗更多 token，不是每个任务都需要。日常编码任务不需要 5 个 reviewer 的面板。判断标准是"它真的需要更多算力吗？"

**实用技巧：**
- 详细提示 + 具体模式描述效果最好
- 可以用"quick workflow"做轻量对抗审查
- 搭配 /goal 和 /loop 实现定时重复执行
- Token 用量可以设预算上限（"use 10k tokens"）
- 工作流可以保存到 ~/.claude/workflows 或打包进 skill 分发给团队。打包时建议提示 Claude 把工作流当模板而非逐字脚本

## 运行AI原生工程团队【⭐⭐】

**来源：** Claude Blog
**链接：** https://claude.com/blog/running-an-ai-native-engineering-org
**关键词：** AI原生团队、agentic coding、工程管理、代码审查、团队组织变革

### 摘要

Anthropic 工程总监 Fiona Fung（Claude Code 和 Claude Cowork 团队）在 Code w/ Claude SF 2026 上分享了 agentic coding 成为默认工作方式后，工程团队的流程和组织发生了怎样根本性的变化。

**核心变化：**

1. **瓶颈转移**：写代码、写测试、重构不再是瓶颈——验证、代码审查和安全成了新的瓶颈。"我们都能快速生成大量代码了，但问题变成了：这代码对吗？怎么维护？人类怎么跟得上代码审查？"

2. **从长期规划到 JIT 规划**：团队放弃了六个月路线图（第三条月就过时了），转向"即时规划"（JIT planning）。不再写设计文档，改为在 PR 和原型中讨论。流程变成"做原型→让内部用户用→根据反馈迭代"。

3. **"谁改的这段代码"不再有效**：所有 PR 都有 Claude 参与，所以这个问题没意义了。新范式是退回到本质——你到底需要知道什么？直接问 Claude，让 Claude 带着数据和上下文回答。

4. **自动化一切**：每天早上手动汇总客户反馈的仪式变成了自动运行的后台任务。团队原则是：任何重复性问题都问"能不能自动化？"

5. **代码审查的分工**：Claude 处理风格检查、linting、PR 反馈请求、bug 修复、测试补充。人类聚焦在真正需要专业判断的地方：法律审查、安全敏感代码、产品品味和审美。

6. **角色重塑**：PM 开始大量写代码，非传统程序员能做更多工程工作，工程师跨界做内容和设计。

7. **招人标准变了**：Fung 强调两个画像——有产品嗅觉的创造性 builder 和有深厚系统专长的工程师。**原始产出量不重要**，模型已经解决了这个问题。关键是"人类专长真正需要的地方"。

8. **团队自治**：几条不可协商的核心原则外，每个 pod 自主决定如何使用 Claude 做 triage、规划仪式和哪些流程优先"Claudify"。

9. **三个指标**：Fung 建议每个工程 leader 跟踪三个数字，同时警告不要混淆吞吐量和成功——真正的指标是你想解决的问题。

**最有价值的建议**：找到团队里最吵闹的流程（最贵的、最让人恐惧的），问两个问题：它还在发挥作用吗？能自动化吗？Fung 举例说她曾经在一个团队里问了句"我们为什么每周花这么多人开这个会？"——于是会议被取消了。

## 一年AI驱动网络威胁映射：MITRE ATT&CK 框架已不够用【⭐⭐⭐】

**来源：** Anthropic News
**链接：** https://www.anthropic.com/news/AI-enabled-cyber-threats-mitre-attack
**关键词：** AI网络安全、MITRE ATT&CK、威胁情报、自主攻击、Claude Code、Project Glasswing

### 摘要

Anthropic 发布了一份重量级网络安全报告，分析了 2025 年 3 月至 2026 年 3 月间被禁的 832 个恶意账号（从中筛选出有足够细节做深度评估的案例），将其行为映射到 MITRE ATT&CK 框架。部分结果已发表在 Verizon 2026 DBIR 报告中，这次是更详细的分析版本。

**三个核心结论：**

1. **AI 让攻击者在攻击后期阶段更危险**：832 个账号中 67.3%（560 个）用 AI 编写恶意软件，这是最常见的 AI 应用。但更关键的是攻击重心正在后移——AI 辅助的账户发现（入侵后识别有效账户）使用率上升了 8.9%，而 AI 辅助钓鱼（初始入侵手段）下降了 8.6%。这些"入侵后"技术过去需要高技术水平才能执行，现在 AI 替低水平攻击者代劳了。

2. **风险评估的老方法失效了**：过去用"使用了多少种技术"和"通过什么平台"来判断攻击者风险级别。但现在 AI 抹平了技能差距——最低技能的攻击者平均使用 16 种技术，最高技能的是 20 种，差距很小。用 Claude Code、API 还是聊天界面也不怎么影响风险等级。真正有区分度的信号是 **AI 被用在攻击链的哪个位置**：高风险攻击者集中在账户发现、横向移动、权限提升等需要实时决策的操作性技术上。但更持久的区分器是"脚手架架构"——高风险攻击者会设计让模型串联攻击各阶段并最小化人工干预的自动化架构。

3. **MITRE ATT&CK 框架缺了一整块**：AI 自主编排攻击步骤、实时决策、无人工干预执行——这些区分最高风险攻击者的关键行为，MITRE ATT&CK 里根本没有对应的技术 ID。他们举了 2025 年 11 月被阻断的国家级间谍行动为例：Claude Code 被操控自主执行命令、利用漏洞、窃取凭证、做出战术决策，仅需极少量人工介入。按 ATT&CK 来看只用了 30 种技术跨 13 个战术，跟中等风险攻击者差不多——但 Anthropic 的风险评分给了满分 100。问题在于没有 ATT&CK ID 能描述"agentic 编排"这种能力。

**前 6 个月 vs 后 6 个月的趋势：** 中等风险及以上攻击者占比从 33% 跳到 56%，增长了约 1.7 倍。整体攻击人口正在向高风险方向迁移。

**Anthropic 的应对：** 已基于这些发现部署了网络防护措施，检测和阻断恶意软件开发和数据批量窃取等行为。正在与 MITRE 讨论 ATT&CK 框架如何演进以纳入 AI 特有行为。在 Frontier Red Team 博客上还发布了交互式攻击技术可视化工具。

**值得注意的关联：** 这份报告与前天发布的 Project Glasswing 扩展公告（覆盖 15+ 国家 150+ 组织）是一体的安全战略——Anthropic 正在系统性地构建从威胁研究到防护部署的完整闭环。

## LLM ATT&CK Navigator：AI网络威胁的可交互映射工具【⭐⭐】

**来源：** Anthropic Red
**链接：** https://red.anthropic.com/2026/attack-navigator/
**关键词：** LLM ATT&CK Navigator、ARiES风险评分、交互式威胁映射、红队、防御方工具

### 摘要

Anthropic 的红队博客（red.anthropic.com）发布了与主站威胁映射报告配套的**交互式 LLM ATT&CK Navigator**，同时公开了更详细的评分方法论。这是 Anthropic News 同日发布的 MITRE ATT&CK 映射报告的技术深度版本，提供了可以直接操作的防御方工具。

**与主站报告的关系：** 主站报告侧重于发现和趋势（已在今日笔记中），红队版本则提供了：(1) 可嵌入网页的交互式 Navigator 可视化工具、(2) ARiES 风险评分体系的完整方法论、(3) 更细粒度的技术统计数据。

**ARiES（AI Risk Enablement Score）评分方法论细节：**

ARiES 是一个加法模型（0-100 分），而非传统的乘法模型。这个选择有明确理由——传统风险公式 Threat × Vulnerability × Impact 在任何一个维度为零时整个分数归零，但在实际中会出现不合理的归零场景：

- **无意中造出武器的场景：** 一个没有恶意意图的用户，用 agentic coding 工具实验时意外搞出了功能性的蠕虫级漏洞利用。意图接近零，乘法模型会把风险归零，但实际上模型确实提供了实质性的攻击 uplift
- **恶意软件已完成但尚未部署：** 攻击者明确有恶意意图，用 Claude 开发了可工作的恶意软件，但没有部署证据。乘法模型又把 impact 归零，风险再次归零。但 AI enablement 信号（攻击者用模型成功开发了恶意软件）恰恰是需要早期捕获的

加法的 ARiES 从三个维度各独立打分：**Threat (0-35)**——意图清晰度、技术复杂度、威胁情报信号、规避检测手段，技术复杂度由 Claude 自己根据用户 prompts 和工具使用来评估；**Vulnerability (0-35)**——模型赋能伤害的能力 + 接口风险（API 和 agentic 工具得分最高）；**Impact (0-30)**——安全分类器打分 + 调查员评估的实际/潜在后果。

**红队版本的独到发现：**

- **技术复杂度不是关键区分器：** 从复合评分中移除"技术复杂度"维度后，832 个账号的风险排名几乎不变（Spearman ρ = 0.96），前 6 名完全一致。高风险的尾部分布不是技术复杂度打分的人为产物
- **技术覆盖面宽度也弱相关：** 技术数量与风险评分仅微弱正相关（r = 0.27）。中位数攻击者使用了 16 种 ATT&CK 技术——放在五年前这会被认为是大规模、资源充足的操作，现在只是平均水平
- **接口选择不说明问题：** 80% 的攻击者使用了 Claude Code，agentic 工具已经是默认访问方式，而非区分特征。仅用对话界面、仅用 API、或用 agentic 工具的三组攻击者，风险分布统计学上不可区分
- **横向移动是最强风险信号：** 使用了横向移动技术的 54 个攻击者平均风险评分 56.4，比整体均值 46.8 高出近 10 分。其他技术远不及这个预测力

**对防御方的启示：** 红队从这份分析中直接提炼了可操作的检测——更新了 Claude 内置的分类器来检测最高风险行为特征，并扩展了 probe 检测覆盖范围。文章暗示了未来的关键转变方向：当高风险技术（横向移动、凭据窃取、Web Shell）不再是少数人的专属，防御方需要新的区分维度——攻击者构建的"脚手架架构"（scaffolding），即串联攻击各阶段的自动化代码和工具链。MITRE ATT&CK 框架还没有对应的 ID 来描述这种自主编排能力。

## Claude 合作伙伴网络推出 Services Track 和 Partner Hub【⭐⭐】

**来源：** Anthropic News
**链接：** https://www.anthropic.com/news/services-track-partner-hub
**关键词：** Claude Partner Network、Services Track、Partner Hub、企业服务、合作伙伴分级、MCP

### 摘要

Anthropic 宣布了 Claude 合作伙伴网络的两项重要扩展：**Services Track（服务分级）**和 **Claude Partner Hub（合作伙伴中心）**。这是 3 月启动的 Claude Partner Network（1 亿美元投入）的后续动作。

**背景数据：** 自 3 月启动以来，已有超过 40,000 家公司申请加入，超过 10,000 名顾问获得 Claude 认证。全球最大的专业服务公司都在建立 Claude 实践——Accenture 培训 30,000 人、Cognizant 向 35 万员工推出、Deloitte 覆盖 47 万人、KPMG 覆盖 27.6 万人、Infosys 在构建行业专属 agent、PwC 从美国团队开始推广 Claude Code 和 Cowork。

**Services Track 三级体系：**

1. **Select（入门）：** 至少 10 名活跃认证人员 + 过去 12 个月至少 2 个已部署联合客户 + 至少 1 个公开客户案例
2. **Preferred（进阶）：** 至少 100 名认证人员 + 至少 15 个已部署客户 + 至少 3 个公开案例
3. **Global Premier（顶级）：** 至少 1,000 名认证人员 + 至少 100 个已部署客户（覆盖 3 个以上区域）+ 至少 15 个公开案例 + 有指定高管赞助的联合业务计划

衡量标准是统一的——不管你是 10 人 AI 原生工作室还是全球咨询巨头，同一个门槛。小公司通过扩大认证团队来爬梯子。

**三个硬指标：** 认证实践者数量（个人认证，通过 Partner Academy 考试获得，要求过去 90 天内使用过 Claude）、生产环境运行的客户数、愿意公开背书的客户案例数。每季度验证，数据双方透明可见。

**Partner Hub：** 合作伙伴可以看到自己离下一级还差多少（每日刷新），客户可以在公开目录中按层级和实际交付能力筛选服务商。还有一个亮点——可以通过 **MCP connector** 把 Hub 连接到 Claude，直接在 Claude 里问"我们离下一级还差什么？""某个 deal 状态如何？"并直接采取行动。

**升降级规则：** 晋升每年两次（1 月 1 日和 7 月 1 日），2026 年额外加一次 10 月 1 日的评审。降级只在年度评审（12 月 31 日）时进行，且只有不符合要求时才会降，提前 90 天通知并给补差机会。服务实践和带新客户是两条独立的奖励通道。

**行业意义：** 这是 Anthropic 从"模型公司"向"企业平台公司"转型的重要一步。通过量化、透明的分级体系，把 Claude 企业落地从零散的项目制变成了有结构的生态。1 亿美元投入 + 可量化的梯子 + 独立的实践和商业通道，这个设计对系统集成商和咨询公司有明确的激励效果。加入是免费的，入门级是 Registered，真正有分量的合作伙伴关系从 Select 开始。
