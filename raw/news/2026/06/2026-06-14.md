## 为啥 Codex 还不推出类似 Claude Design 的产品？【⭐⭐⭐】
**来源：** 宝玉的博客
**链接：** https://baoyu.io/blog/2026-06-13/codex-design-model-gap
**关键词：** Claude Design, Codex, GPT-5.5, Claude Opus 4.8, Harness, 交互原型, 模型能力差距

### 摘要

宝玉深入分析了为什么 OpenAI 的 Codex 至今没有推出类似 Anthropic Claude Design 的产品。核心论点：**问题不在工程层（Harness），而在模型层**。

Agent 产品有两个层次——Harness（提示词、工具链、UI交互流程）和模型（真正干活的大脑）。Claude Design 的 Harness 层技术上没秘密，宝玉自己甚至逆向实现了 baoyu-design，可以让 Claude Design 的 Skill 跑在其他模型上。

真正拉开差距的是模型能力。Claude Design 交付的不是 Figma 那样的静态设计稿，而是融合了设计稿和原型的**高精度可交互原型**——你不仅能看到设计，还能直接上手操作。这对模型的要求极高：必须在动手画 UI 之前，把数据结构、状态管理、交互逻辑全部想清楚，然后一次性交付完整可交互原型。

GPT-5.5 能画好看的静态界面，但做到可交互就力不从心——列表能滚动但 sidebar 不能点，点赞按钮没反应，需要反复迭代多轮。对比之下，Claude Opus 4.8 在设计+架构这类场景上做了大量专项训练，产出物本身就是代码（React + CSS + JSON），设计和开发之间的沟通损耗降到最低。

结论：Codex 不推类似产品是因为模型还没准备好，目前只有 Claude 做到了。领先多久取决于 OpenAI 后续模型的进化速度。
