## Claude 正式登陆 Microsoft Foundry，进入 GA 阶段【⭐⭐⭐】
**来源：** Claude Blog (Anthropic)
**链接：** https://claude.com/blog/claude-in-microsoft-foundry
**关键词：** Claude、Microsoft Foundry、Azure、企业级AI、Opus 4.8、Haiku 4.5

### 摘要
Anthropic 宣布 Claude 模型正式在 Microsoft Foundry 上 GA（Generally Available），托管于 Azure。这是 Anthropic 企业战略的关键一步——Claude 运行在客户的 Azure 环境中，复用企业已有的认证、计费和治理体系，同时 Anthropic 作为数据处理器运营推理。

首批上线的模型是 Claude Opus 4.8 和 Claude Haiku 4.5，通过 Messages API 提供，支持 prompt caching 和 extended thinking。客户可以选择数据处理区域（包括美国数据区），满足数据驻留要求。

几点值得注意的细节：
- **双轨部署模式**：用户可选择 "hosted on Azure"（完全在 Azure 环境内运行，含 Azure 身份认证和计费）或 "hosted on Anthropic"（之前的 Foundry Preview，功能更全但模型范围有限）。Anthropic 表态会逐步实现两边的功能和模型对等。
- **企业合同打通**：符合条件的 Microsoft EA 客户可以用 Azure 承诺消费抵扣 Claude 使用费，统一账单。
- **已经有不少大客户背书**：NVIDIA（Justin Boitano 引用提到在 GB300 GPU 上跑）、Bolt（VP Partnerships 强调企业级可靠性）、核能行业的安全分析公司（Matt Huang 称把 200 人天的安全分析压缩到 1 天）、Momentic（QA 测试平台，每分钟百万 token 级别）。

这是 Anthropic 继 Google Cloud 之后在云平台的又一重大布局。在企业级 AI 赛道上，Anthropic 正在从"模型提供商"转向"平台化"，通过云厂商的渠道和合规能力把 Claude 推入大企业核心工作流。

## Claude 推出 Apps Gateway：自托管的企业级 Claude Code 控制面【⭐⭐⭐】
**来源：** Claude Blog (Anthropic)
**链接：** https://claude.com/blog/introducing-the-claude-apps-gateway
**关键词：** Claude Code、Gateway、企业SSO、Bedrock、GCP、自托管、成本归因

### 摘要
同一天，Anthropic 还发布了 Claude Apps Gateway——一个专门为 Claude Code 设计的企业级自托管控制平面。解决的核心问题是：之前在企业中使用 Claude Code 需要给每个开发者配置单独的云凭证、手动推送配置文件、自己搭建用量监控，极其繁琐。

Gateway 的核心能力：
- **SSO 统一登录**：支持 Google Workspace、Microsoft Entra ID、Okta 等 OIDC Provider，开发者用企业账号登录即可，机器上不留长期凭证
- **集中策略管控**：管理员在 Gateway 上定义 managed settings（允许的模型、默认配置等），客户端登录时自动拉取，每次请求都强制校验
- **用量归因 & 成本控制**：通过 OTLP 上报每个开发者的用量到企业自建的 collector，支持按组织/组/用户设置日/周/月消费上限
- **多云路由 & 故障转移**：Gateway 持有上游凭证，路由推理到 Claude API、Amazon Bedrock 或 Google Cloud，支持多提供商间的故障转移
- **隐私优先**：除非配置使用 Claude API，否则推理流量和用量数据不会发送到 Anthropic

部署方式也很克制：就是一个无状态容器（Linux + PostgreSQL），直接跑在 `claude` 二进制里，不需要额外部署新服务。同时 Anthropic 还开源了 Gateway 使用的协议，允许其他 Gateway 开发者实现相同功能。

结合前一篇 Foundry 的发布，Anthropic 今天的企业级组合拳非常清晰：Foundry 解决"在哪跑"（Azure 托管），Gateway 解决"谁来管"（企业自托管控制面）。这基本把 Claude 的企业落地路径画完了。

## "It's Hard to Eval" 是产品异味——Hamel Husain 的评估设计哲学【⭐⭐】
**来源：** Hamel Husain (个人博客)
**链接：** https://hamel.dev/blog/posts/eval-smell/
**关键词：** AI评估、产品设计、可验证性、数据Agent、用户体验

### 摘要
Hamel Husain（前 GitHub、现独立 AI 顾问，过去 3 年专注 AI 评估）写了一篇很有洞察力的文章。核心观点：当团队说"我们的产品很难评估"时，这不是评估问题，而是产品设计问题。

文章的核心推理链条：
1. 如果一个产品的输出让你（构建者）都难以验证，用户更验证不了
2. 最坏情况下，用户得从头重做才能确认输出对不对——这和 AI 提效的初衷完全矛盾
3. 应该在设计产品时就考虑可验证性，而不是事后补评估

Hamel 用三个实际咨询案例展示了设计模式：
- **AI 数据 Agent**：别只输出最终答案（$4.21M），要附带可检查的中间产物——SQL 查询、中间计算、与可信源的对比、无法验证的项标记出来。用 Chat + Notebook 双视图，透明度是信任的基础。
- 后端代码生成、合规文档生成等类似场景也有对应设计。

这篇文章和最近业界对"AI 产品不应该只是黑箱"的讨论高度一致。值得所有做 AI 产品的团队读一读。

## 今日总结

今天最大的主题是 **Agent 插件/技能生态的全面爆发**。Anthropic、OpenAI、Google、AWS 四家大厂几乎同时推了自己的 agent 插件/技能体系，NVIDIA 跟进安全扫描工具，加上社区热门的 addyosmani/agent-skills（68k stars）和 hermes-agent（206k stars），一个明显的趋势是：agent 的能力边界从 prompt engineering 转向可组合、可复用、可审计的插件模块。

同时 Anthropic 还打出了企业落地的组合拳——Foundry GA（Azure 托管）+ Apps Gateway（自托管控制面），Claude Code 的企业化路径非常清晰。

模型层面，GLM-5（Agentic Engineering）、LTX-2（音视频生成）、VoxCPM2（免 tokenizer TTS）各有突破。开发者工具方向，OpenSpec 的 SDD 方法论（58k stars）和 UI-TARS 的 agent 中间层（37k stars）代表了两个重要方向：怎么让 AI 写出更好的代码，以及怎么让 AI 更好地操作软件。
