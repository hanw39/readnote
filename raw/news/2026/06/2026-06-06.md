## Making Claude a chemist【⭐⭐⭐】
**来源：** Anthropic Research
**链接：** https://www.anthropic.com/research/making-claude-a-chemist
**关键词：** Claude化学能力、NMR光谱分析、ChemDraw对比、多模态科学应用

### 摘要

Anthropic 发布了将 Claude 引入化学领域的第一份白皮书，由公司内部化学家 David Kamber 主导。核心结论：Claude 开始在化学家的日常工作中产生实际帮助。

化学家的工作涉及在不同表征之间切换——手绘结构图、仪器读数（NMR光谱）、数据库查询、专利文献中的技术符号等。这些表征编码了相同的化学信息，但每种都需要不同的理解方式。CAS（全球最大化学注册库）收录了超过 2.9 亿种化合物，每天新增约 1.5 万种，靠人工翻译根本跟不上。

白皮书重点测试了 Claude 在 NMR 光谱（核磁共振，化学家最常用的分析手段）上的表现。测试了三款 Claude 模型（Opus 4.7、Opus 4.6、Sonnet 4.6），对比专业化学软件 ChemDraw 和 MestReNova，在 20 个合成化学预印本中的化合物上进行评估（这些化合物发表于模型训练截止日后，避免数据污染）。

关键发现：
- Claude Opus 4.7 在 NMR 预测和结构解析上展现了与专用软件竞争的能力
- 相比传统 ML 工具，Claude 的优势在于多模态能力——可以直接从期刊图片或手绘草图中读取化学结构，不需要预先整理好的分子数据库
- 能逐步展示推理过程，化学家可以审计输出结果

Anthropic 的态度很务实——承认 AI 在化学领域的应用仍然"很大程度上是愿景"，数据问题（零结果缺失、格式不一致、付费墙）依然存在。但他们认为当前前沿模型的多模态和显式推理能力，改变了"哪些问题变得可解"。文章还提及历史上化学中的镜像分子悲剧（沙利度胺灾难，镇静剂变致畸剂），强调结构识别的重要性。

横向对比：这是 Anthropic 继数学（IMO）、编程之后，在专业科学领域的最新发力。与 Google DeepMind 的 AlphaFold（蛋白质折叠）不同，Anthropic 走的是通用模型+领域适配路线，直接用 Claude 的多模态能力去理解化学的多种表征形式，而非训练专用模型。

## Introducing the Google Colab CLI【⭐⭐】
**来源：** Google AI
**链接：** https://developers.googleblog.com/introducing-the-google-colab-cli/
**关键词：** Colab CLI、GPU即服务、AI Agent工具、远程执行

### 摘要

Google 发布了 Google Colab 命令行工具（CLI），把 Colab 的高性能计算能力从 Web 界面搬到了终端。核心卖点是"零摩擦"——不用手动配置云实例，一条命令就能获得 GPU/TPU。

主要功能：
- **即时机型选择**：`colab --gpu A100` 或 `colab --gpu T4`，直接请求对应加速器
- **远程执行**：`colab exec -f script.py` 把本地 Python 脚本扔到 Colab 运行时跑
- **产物回收**：`colab download` 下载模型和数据，`colab log` 保存可回放的 .ipynb 日志
- **交互式环境**：`colab repl` 或 `colab console` 进入远程交互会话

最有趣的设计：**专为 AI Agent 打造**。CLI 包含预打包的 Colab skill 文件，Agent（Antigravity、Claude Code、Codex 等）可以直接读取并调用。官方演示用 Antigravity agent 在 T4 GPU 上完整跑了一个 QLoRA 微调 Gemma 3-1B 的流程——从申请 GPU、安装依赖、运行微调脚本、下载 adapter 模型到清理环境，全部由 Agent 通过 CLI 自动完成。

横向对比：类似 Modal 或 Replicate 的 serverless GPU 方案，但 Colab CLI 更轻量，且与 Google 生态（Gemma 模型、Colab notebooks）深度绑定。对独立开发者和 AI Agent 编排场景特别友好。6天前 Google 刚发布 Gemma 4 12B（参看 6月3日的资讯），这次 CLI 工具显然是为了让开发者更快上手 Gemma 模型微调。

## The Claude Cowork product guide【⭐⭐】
**来源：** Claude Blog
**链接：** https://claude.com/blog/the-claude-cowork-product-guide
**关键词：** Claude Cowork、知识工作agent、产品指南、跨应用工作流

### 摘要

Anthropic 发布了 Claude Cowork 的正式产品指南，详细介绍了这个"知识工作 agent"的定位和使用方式。

Cowork 的定位很清晰——不是对话式 AI，不是编程工具，而是在两者之间的"知识工作"层。它在 Claude 桌面端运行，能读写本地文件，连接 Slack 和 Google Drive 等应用，执行多步骤任务并产出真正的交付物（文档、表格、邮件），附带回源文件的引用。

指南核心内容：
- **工具矩阵**：何时用 Claude chat（对话起草）、Claude Code（编程）、Claude Cowork（跨应用知识工作）
- **核心能力**：本地文件访问、子代理（subagents）、长时运行任务、定时任务（scheduled tasks）
- **权限模型**和系统要求
- **7 种常见工作流**：研究简报、会议准备、周期性报告等
- **插件生态**：营销、产品管理等专用插件

横向对比：Cowork 本质上是在和 Microsoft Copilot（深度 Office 集成）、Google Duet AI 竞争"AI 办公"场景。区别在于 Cowork 是桌面端 Agent 而非云服务嵌入，强调本地文件控制和跨应用编排。配合 Anthropic 前一天发布的"GTM 工程"案例（同一位销售用 Claude Code + Cowork 改造团队工作流），这是 Anthropic 在企业知识工作场景的系统性布局。

## How one Anthropic seller rebuilt his team's workflows with Claude Code【⭐】
**来源：** Claude Blog
**链接：** https://claude.com/blog/how-anthropic-uses-claude-gtm-engineering
**关键词：** Claude Code企业应用、销售自动化、GTM工程、零编程基础

### 摘要

Anthropic 发布了一篇内部案例：销售 Jared Sires 如何用 Claude Code 从零构建自动化工具，最终改变了整个销售团队的工作方式。

关键故事线：
- Jared 2024 年加入 Anthropic 前从未写过代码，是一个管理 600-700 个客户的客户经理
- 每天 10-15 个客户电话，晚上回邮件到 9-10 点，收件箱几乎不可管理
- 他用 Claude Code 从零构建了 **CLAFTS**（Claude Drafts）——一个嵌入 Gmail 的应用，用 Claude API 自动起草客户邮件回复
- CLAFTS 每天为他节省 2-3 小时，分享到 Slack 后 24 小时内销售团队其他人也开始使用
- 他的角色因此转变为 GTM（Go-To-Market）产品经理，专门发现销售流程中的问题并用 Claude 构建解决方案
- 后续工具：自动研究客户背景（会前简报）、从会议记录生成跟进邮件、客户使用量排名分析（帮助识别重点客户）
- 所有工具打包成 Claude Cowork 插件，整个销售团队可用

Anthropic 借此传递的信息：Claude Code 不只是给程序员的工具，非技术角色也能用它解决真实的业务问题。"这是我经历过最 empower 的事情"——Jared 的原话。

横向对比：这类案例在企业软件领域并不新鲜（Salesforce、Zendesk 等都有类似故事），但由 AI 公司的内部案例来讲述，且有零编程基础到"构建团队级工具"的真实路径，说服力更强。配合 Claude Cowork 产品指南同时发布，形成"工具 + 案例"的组合拳。

## Improved performance and model support with GGUF【⭐⭐】
**来源：** Ollama
**链接：** https://ollama.com/blog/improved-performance-and-model-support-with-gguf
**关键词：** Ollama 0.30、GGUF、llama.cpp、Vulkan、本地模型推理

### 摘要

Ollama 发布 0.30 版本，核心更新是深度集成 GGUF 生态和显著性能提升。

主要更新：
- **NVIDIA 性能提升 20%**：在 RTX 5090 上运行 Gemma 4 26B（Q4_K_M 量化），吞吐量比上一版本快 20%，归功于 NVIDIA 和 llama.cpp 团队的联合优化
- **Vulkan 默认启用**：AMD 和 Intel GPU 用户现在开箱即用 GPU 加速，不需要装厂商专用驱动
- **GGUF 模型兼容性大幅扩展**：支持 LFM、Prism 等新模型家族，以及 Unsloth 发布的微调模型
- **从 Hugging Face 直接运行 GGUF**：下载 GGUF 文件或目录 → 创建 Modelfile → `ollama create` 即可运行
- **Coding Agent 集成**：如果模型支持 tool calling，这个能力在 Ollama 中依然可用。展示了直接启动 Claude Code、Hermes Agent、OpenClaw 的命令：`ollama launch claude --model my-model`

横向对比：Ollama 0.30 是在 llama.cpp GGUF 生态日趋成熟背景下的重要更新。Vulkan 默认启用降低了对 NVIDIA 的硬依赖，对 AMD/Intel 用户更友好。GGUF 兼容性扩展让 Ollama 从"Ollama 专属模型"走向"GGUF 标准模型"，生态开放度提升。Coding Agent 直接集成的设计（`ollama launch claude --model xxx`）降低了本地模型+Agent 编排的门槛，与 Google Colab CLI 的 Agent 友好设计形成呼应。
